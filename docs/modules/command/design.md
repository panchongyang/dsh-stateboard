# 命令总线模块设计

> 文档定位：L3；结果与兼容以 [L1 命令信封](<../../CONTRACT.md#21-命令信封错误码与-http-映射>)为准，内部调用见[模块契约](<contract.md>)。

## 1. 职责与非职责

核心命令路径接收已建立身份的请求，在同一项目的串行位置内准备、校验并提交。它不认证网络请求，不执行证据材料，不跨项目事务，也不承诺撤销编辑器、部署或测试的外部副作用。

## 2. 请求到发布

1. [application](<../../../lib/core/application/index.js>)统一请求 DTO；[runtime](<../../../lib/core/runtime/serial-command.js>)取得项目串行位置，不把 writer 返回给协议层。
2. [命令组装入口](<../../../lib/core/commands/transaction.js>)生成稳定命令身份与准备操作。[事务模型](<../../../lib/core/transaction/model.js>)在已提交值上核对去重和项目 CAS，再在私有工作态中准备恢复、到期回收与必要首绑。
3. 处理器从一份只读样本和显式观测端口计算值操作。业务层决定资格；[领域操作](<../../../lib/core/domain/operations/tasks.js>)在模型内保证合法转移、引用和版本，不从公开命令名猜内部操作。
4. 模型整批执行、校验并派生事件，从物理层取得单一 `seq/hash` 回执再发布。读端接收已发布值，不观察暂存实体、租约或未完成记录。

[写入时序](<../../diagrams/command-write.svg>)展示入口、模型事务、介质与读模型各自的边界。

## 3. 为什么准备、耐久和发布分开

- **业务和冷恢复同批**：先单独写恢复会导致业务拒绝却推进版本；先算业务再回收可能用旧值覆盖结果。模型私下准备恢复，实体 CAS 以调用方能读到的已提交修订为准；业务需要持久化且成功才一起发布。
- **物理回执而非状态别名**：持久化只证明所请求字节已耐久，不决定模型状态。回执或发布结果不确定就封闭 writer，冷开按日志与原 `cmdId` 对账。
- **一次操作与一次业务命令不同**：一笔命令可包含多项具名操作，所有正式记录一起发布，不向命令处理器提供部分写权。成功的空操作、去重或仅运行态续租不伪造新日志。
- **外部 I/O 不宣称跨资源原子**：文件观测和必要的 blob/留存对象预写有独立边界，公开版本只来自已提交引用；搬迁后置元数据同步失败返回 warning，快照也不决定提交结果。

## 4. 失败与验证

CAS、授权或业务守卫拒绝时，不发布本次准备的状态、租约、绑定或成功事件。读端仍能提供已有提交事实；显式生命周期、资料修复和数据恢复有自己的授权，不是普通命令的隐含前置步骤。
