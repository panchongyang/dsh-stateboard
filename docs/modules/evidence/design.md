# 证据模块设计

> 文档定位：L3；对外行为见 [L1 验收项与证据](<../../CONTRACT.md#验收项与证据>)，调用约定见[内部契约](<contract.md>)。

## 1. 材料不是验收证明

证据把提交者与材料、验收项、版本和替代历史连起来。`file` / `doc` 有服务端采样，`command` / `test` / `note` / `url` 保持提交者材料身份，不执行、不联网、不验证结论。验收项覆盖、源内容可验证、验收者裁决是三件事。

## 2. 读取、留存与提交

1. [归一化](<../../../lib/core/evidence.js>)解析材料并从实际所属根观测字节。工作区 hash 包含 BOM 和换行，内嵌正文走自己的历史 blob。
2. [工作区对象端口](<../../../lib/core/adapters/retained-documents.js>)安全发布或复用同内容不可变对象；编辑器中的原件不写入。只观测到当前 hash 时，不生成不可变版本引用。
3. [任务命令](<../../../lib/core/commands/task-evidence.js>)准备 active 材料并一次审计，模型把留存事件、证据与任务状态作为同一日志事实发布。对象先于日志存在，不意味着它已被引用或可以被搜索。
4. [内容审计](<../../../lib/core/evidence.js>)按来源类型读取：current-only 观测当前文件，工作区留存读校验后的原版本，历史 Git 只校验记录域。它们都不改文档状态或确认基线。

历史 Git 索引是不可变的来源记录，不是可访问仓库的 capability。保留它是为了可追溯和事件兼容，不为了用未核验的字节填补历史。

## 6. 失败、降级与恢复

权限失效、缺对象、对象损坏和当前文件漂移是不同的事实。故障不会从当前文件合成过去的正文；有同一 contentHash 的独立一致性备份才可恢复留存对象。不能恢复时保留记录和明确缺口。最低支撑路径见[恢复指南](<../../operations/RECOVERY.md>)，人工处理和验收边界见 [L1](<../../CONTRACT.md#12-任务状态机>)。

## 7. I/O 成本

采样、对象校验和证据再审计有独立的读 I/O；简报不做完整审计，真正的 health 使用隔离路径。图片字节不进入取证流水线，[图片读取](<../documents/design.md#6-图片是只读资源旁路>)的正文与资源读取成本另计。产品读取和审计不启动 Git 进程。
