# 历史知识读取模块设计

> 文档定位：L3；行为权威为 [L1 知识读取与检索](<../../CONTRACT.md#历史知识读取与检索>)，内部约定见[内部契约](<contract.md>)。
> 已实现的两层读取；验证范围见[验证记录](<../../decisions/history-knowledge-validation-2026-11-14.md>)。宿主是否生效取决于部署。

## 1. 职责与非职责

知识读取把项目已留存的任务、计划、事件、登记文档、证据、审查记录与已有关系组织成可重建索引：先返回搜索碎片，再由调用者沿稳定引用回读原文与有界上下文。

**非职责**：

- 不生成记忆、不裁决约束有效性、不把相关性当适用性。
- 不改变权威日志、领域写模型、提交、验收或任务事务。
- 不扫描整个工作区；外置正文只能经登记文档或任务证据进入。
- 不预建历史基线重置、截断或新的事实库生命周期。
- 不引入 Embedding、向量库、GraphRAG 或独立约束实体。

## 2. 来源与“历史原文”

| 来源 | 索引内容与定位 | 边界 |
|---|---|---|
| 任务 | 标题、描述、验收要求、记录说明；定位 commit、事件位置、字段与任务版本 | 搜索展示最新匹配版本，historyRef 展开旧版本 |
| 计划 | 头与各内容版本的名称、描述、阶段、正文 | plan ID 是身份，version 是内容版本；管理 rev 不是内容版本 |
| 事件与交接 | 可公开字段、checkpoint/handoff、执行意图与结果 | additive 事件也可独立命中；只读 current state 会漏掉 |
| 登记文档 | 元数据、内嵌正文、可读外置正文、已记录固定版本 | 外置 metaRev 不等于正文版本；未保留的旧字节不可恢复 |
| 证据 | kind、ref、summary、hash、验收关联、提交者与替代 | file 仅在可证明项目路径与内容身份时读取；不猜路径 |
| 审查 | lastAudit、报告、清单、结论、范围与证据指纹 | 记录“谁报告了什么”，不转成系统正确性事实 |
| 关系 | 任务依赖、planRef、文档 links、证据到验收、明确替代 | 查询期按水位展开；不生成语义推断关系 |

历史原文指记录中的原始字段或结构化内容，不是含内部租约、执行凭据、本机绑定根与绝对文件引用的完整 commit。字段省略、正文截断与分页必须显式；不同版本不能拼成一段“完整历史”。

未被记录、观察或保留的内容不承诺追溯补齐；只有引用/hash 而没有可用正文的外置材料不算已留存。源对象丢失报告缺失，不能用索引恢复或用当前正文替代。

## 3. 两层读取与引用身份

统一 core 读取服务，DSH 原生工具与 MCP 提供同名两个薄适配入口，共享业务 schema、描述、原文与来源/覆盖返回。DSH 按受信会话 cwd 定位项目；MCP 使用项目工作会话授权。具体字段以 [L1](<../../CONTRACT.md#历史知识读取与检索>) 与 [shared](<../shared/contract.md>) 为准。

1. **search**：关键词、可选来源类型、结果/关联预算、分页游标、调用者 discovery 线索；返回碎片、来源引用、命中信息、来源版本、覆盖情况。
2. **read**：一个或少量引用、原文/上下文模式、字节预算、续读游标；返回公开原记录或正文块、已有关系、可继续展开的引用、内容身份、缺失与截断状态。

第一层优先摘录描述、说明、验收条目等业务原文，保留引用与版本；定位 hash 与 actor 在第二层提供。第二层展开所属记录、正文块和必要前后文，单次最多自动附带一跳已有关系；更多跳转由 Agent 主动查询。直接命中、已有关联发现与调用者 discovery 线索分别标识，不把动态联想写成正式关系，也不设累计思考轮次门禁。

引用绑定项目、来源类型、实体 ID、commit seq/hash、事件位置与字段/章节；正文引用再带 rev、hash 或固定 Git 身份。数据库行号与索引代号不是持久引用。重建后相同仍可用来源的引用继续可解析。引用不是授权：每次读回都校验项目范围、来源存在性与身份，不接受任意路径、URL 或跨项目拼接。

任务板只控制单次资源/响应成本与自动附带的一跳关系，不承担模型思考流程门禁。不同版本不混为一段；只有稳定 ID 的关系返回关系声明及候选引用，并标明目标读取水位。

## 4. 索引与生命周期

[reader](<../../../lib/core/knowledge/reader.js>) 在已授权项目上执行 search/read；独立 worker 读取已验证发布前缀，不打开 writer、不续租、不恢复任务。派生索引位于独立本地缓存目录，不写入权威 store 的 meta、commits、snapshot 或 blobs。

- 首次授权查询按需建立来源清单与索引；没有查询不持续运行。
- 后续调用按已验证水位追赶，不另启常驻后台循环；进度只在一个完整 commit 的材料处理完后前移。
- 重建在独立事务中重置并发布已校验批次；增量在同一派生事务发布数据与水位。分批重建公开落后范围，不假装完整。
- 索引落后但与源历史同源时，可返回已有范围并标记落后；日志缩短、替换、回退或身份无法证明时停止把旧索引当当前结果。
- 每次请求结束释放 worker 和内存；再次调用继续核对缓存与已留存来源。关闭、超时或 worker 失败只影响检索请求，不影响任务操作。

[build](<../../../lib/core/knowledge/build.js>) 按需追赶；[sqlite-index](<../../../lib/core/knowledge/sqlite-index.js>) 使用 Node 内置 SQLite FTS5/BM25，contentless-delete 表不保存可回读正文，片段与原文从来源回读。索引格式带版本，损坏或不兼容时失效重建。SQLite/FTS5 不可用时复用同一来源适配与引用契约，降为有界关键词计分，明确引擎、覆盖与预算耗尽，不标成 BM25，也不要求安装扩展。

查询接受普通关键词，不开放原始 SQL/FTS 表达式；词项做 NFKC/小写归一，中文保留单字/双字组合，英文标识符保留完整形式与组成部分。具体实现见 [terms](<../../../lib/core/knowledge/terms.js>)。

## 5. 覆盖、一致性与失败

每次响应区分：

1. **已知材料**：纳入哪些来源、已验证/已索引到哪些日志范围；未纳入或未读取的数量与原因。
2. **观测状态**：外置材料的观测时间、内容身份、可读性与变化；日志水位不证明外置正文最新。
3. **返回范围**：候选、原文与关联是否截断，是否还有游标或未展开引用。

complete 只相对明确列出的材料范围与读取水位，不表示记录了全部历史或恢复了全部约束；零命中不等于不存在。返回前复核 writer 发布前缀与正文观测，旧缓存不能掩盖来源变化、撤销登记、绑定失效或授权撤销。

外置/Git 继续服从 documents/evidence 的安全边界：不抓取任意 URL、不重跑 command/test、不读远端 LFS、不运行 filter/textconv/hook。撤销登记、绑定失效或权限撤销后停止当前正文读取与命中交付；历史登记仍可追溯，固定历史继续按既有授权与内容身份校验。

## 6. 成本与阅读顺序

单宿主独立 worker 名额、截止时间、分页与批次预算按 [L1](<../../CONTRACT.md#历史知识读取与检索>) / [shared 定义](<../../../lib/shared/knowledge.js>)执行；索引正文预算不是整个请求 I/O 上限。读取不要求 claim/begin/verify，也不因查询创建项目或绑定。

阅读顺序：[reader](<../../../lib/core/knowledge/reader.js>) → [worker](<../../../lib/core/knowledge/worker.js>) → [snapshot](<../../../lib/core/knowledge/snapshot.js>) / [records](<../../../lib/core/knowledge/records.js>) / [content](<../../../lib/core/knowledge/content.js>) → build/sqlite-index → [search](<../../../lib/core/knowledge/search.js>) / [read](<../../../lib/core/knowledge/read.js>)。验证矩阵与未覆盖限制见[验证记录](<../../decisions/history-knowledge-validation-2026-11-14.md>)；不以离线通过声称部署生效或真实约束恢复效果。
