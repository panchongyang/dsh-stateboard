# 项目文档外置：开源前置实施计划

> 状态：待实施计划。创建计划和登记依赖不代表实现、验收、真实数据迁移、合入、部署或公开发布获准。

## 1. 目标与边界

首个开源版本必须具备工作区文档管理形态：文档正文由项目工作区持有、通过 Git 管理，看板负责引用、关系和管理现状。项目自身的文档组织和对外说明必须与此一致。

本计划与“看板自身状态是否存进项目”独立：任务、计划、租约、事件日志、执行密钥、确认状态和本机绑定继续使用现有用户级存储。本计划不引入完整项目内状态存储、跨机同步、多人权限或离线多主合并。

正文是项目资产；看板元数据是看板状态。正文随 Git 不意味着 clone 后自动得到任务历史、文档登记和人工状态。首版通过显式看板数据备份/导入迁移这些元数据，不新增双向同步的 Git 元数据清单。

## 2. 目标契约

### 2.1 所有权与操作

- 文档可以位于项目工作区中的任意获准位置；不强制统一目录、frontmatter 或看板编辑器。
- 显式登记文档；扫描只提供候选，不自动收录所有 Markdown，不自动向 Git 添加、提交或公开文件。
- docId 表示稳定登记身份；locator 表示可更新的位置。移动后通过显式重定位保留身份和关联，不以同名或相同 hash 自动接管文件。
- 看板可保存标题别名、分类、任务/计划关联、管理状态、确认内容引用和元数据修订号，不保存新文档正文 blob。
- 解除登记不删除文件；归档不删除文件。首版提供读取、预览和元数据管理，不建设通用文件编辑器。

### 2.2 状态分离

| 维度 | 语义 | 来源 |
|---|---|---|
| 管理状态 | 草稿、待评审、采用中、归档；精确转换规则在 D1 冻结 | 显式管理操作 |
| 可用性 | 可读、路径不存在、根不可用、无权限、越界、非普通文件、超限或格式不可预览 | 所选工作区的观测 |
| 确认情况 | 未确认、与确认基线一致、确认后有更新 | 当前内容与显式确认基线比较 |
| Git 状态 | 未跟踪、被忽略、未提交修改、已提交 | Git 观测 |

读取和刷新不推进确认基线，不自动改变管理状态，不因轮询写入元数据版本或事件。观测可使用有界缓存并显示上下文和时间；正式确认/提交证据必须重新验证，不能把 mtime/size 当内容证明。

内容变化对日常引用是信息，不直接报告证据损坏。文件不可用时保留登记项、标题、关联、管理状态和确认引用，给出可操作的原因分类；不能仅凭 ENOENT 推断删除、改名或换分支。check-ignore 只说明忽略规则。安全拒绝和存储损坏须与普通路径不可用区分。

### 2.3 工作区与身份

- 复用开源身份任务的稳定 projectId、本机绑定和冲突处理，不另建仓库身份体系。
- 默认读取项目主工作区。多 worktree 的文档阅读只能使用显式获准绑定，并显示所选上下文；首版至少完成主工作区闭环，对尚未实现的上下文明确拒绝。
- 会话 cwd 不能隐式切换共享文档根、主工作区或现有 file 证据根；不得跨工作区搜索同名文件作为降级读取。
- locator 使用绑定标识与绑定根相对路径。本机绝对路径属于本机绑定，不写入可移植文档内容引用。
- Git common-dir 可辅助本机绑定发现，但不是跨机 repoId；分支名、remote URL、目录名不作为唯一身份。

### 2.4 安全正文读取

提取可共享的路径解析和文件检查底层，复用已有词法/realpath containment，但不复用 evidence 的漂移严重级别和生命周期规则。正文读取必须有普通文件、链接越界、实际读取字节上限、编码/预览格式、读取中变化和错误分类的明确契约；不能用先 stat 后无限读替代有界读取。

首版以 UTF-8 Markdown/文本为可预览范围；其他文件可登记但须显示不支持预览。相对链接/图片仍受工作区与注册资源边界约束，不提供任意宿主路径读取或执行。精确大小、允许格式与可预览资源边界在 D1 冻结。

### 2.5 当前引用、确认基线与固定证据

- 日常关系引用 docId，读取所选工作区当前内容。
- 确认操作明确记录所确认的内容身份和阅读上下文；观察 hash 与确认 hash 分离。
- 可重放的正式文档交付证据固定到显式仓库绑定、commit OID、当时的仓库相对路径及 blob OID/内容校验值；不能只写可变 branch、当前路径或 docId@元数据rev。
- 工作区字节与 Git blob 字节可能受换行、过滤器或 LFS 影响；须定义比较与校验域，不能混用 hash。支持范围、拒绝与降级在 D1 明确，不能静默提交另一份 HEAD 内容充当脏工作区证据。
- 草稿阅读不要求 commit；正式可重放证据要求内容已提交并可取回。未提交内容若需要留证，先由用户在其工作区保存并提交，不由看板持有隐形正文快照。
- 固定证据审计其固定来源，不因工作区正文演化或切分支判定漂移；固定对象不可取与内容校验失败分别表达。说明持久 Git ref/对象保留和备份要求，hash 不是可用性保证。
- 内容引用只证明指定版本，不证明已合入、部署或通过验收；保留现有 file 证据主工作区策略，不借 worktree 绑定绕过合入要求。

### 2.6 版本与兼容

新外置登记、正文内容身份和管理元数据版本显式区分。元数据更新仍需乐观并发检查；正文读取不增加元数据 rev。

现有 docId@rev 和 hash 的历史含义不得重解释。按证据所存 hash 与历史事件/旧 blob 建立可恢复映射，不能把最新正文伪装成历史版本。缺失内容须列为不可恢复并由用户处置。

事件兼容按新语义事件或显式可拒读版本处理。不能只在既有 doc/updated 塞入 path 就假设旧读方自动 fail-closed。设计覆盖回放、快照、MemoryStore、health/fsck、repair/salvage、工具/HTTP/客户端与降级；代码回退和数据快照/RPO一起定义。

## 3. 分期与任务

新计划各任务均设置人工审核；本轮不 claim、不 begin、不运行实现或迁移。

| 阶段 | 任务 | 主要交付 | 依赖 |
|---|---|---|---|
| 一：契约 | D1 契约、数据模型与兼容决策 | API/事件、状态维度、读取限制、内容身份、迁移与回退设计；人审冻结 | 无，可与首发决策并行 |
| 二：核心 | D2 安全有界工作区正文读取 | 共享 resolver/reader、明确可用性、路径和并发读取安全回归 | D1 |
| 二：核心 | D3 登记、现状及工具/HTTP接口 | 外置文档登记、元数据并发、关联、确认基线、显式工作区绑定与查询 | D2 + 既有开源身份任务 |
| 三：使用与证据 | D4 文档现状管理界面 | 预览、上下文、分维状态、不可用态、登记/重定位/解除登记与人工验收清单 | D3 |
| 三：使用与证据 | D5 Git固定内容引用与证据 | 固定版本解析/读取/审计，当前引用与固定证据隔离 | D3 |
| 四：迁移与组织 | D6 内嵌文档导出与迁移工具 | dry-run、映射清单、历史引用恢复、幂等/中断恢复、备份回退 | D3 + D5 |
| 四：迁移与组织 | D7 本项目文档归位与迁移留证 | 经用户确认的文档去向、真实数据授权迁移、拟公开材料脱敏、Git归位和旧引用核对 | D4 + D5 + D6 |
| 五：独立验收 | D8 集成候选回归与非实现者审查 | 冻结候选、完整门禁、故障/兼容/恢复矩阵和独立审查 | D4 + D5 + D6 + D7 |
| 六：人工闸门 | D9 文档外置开源前置人工验收 | 同一候选人工确认、项目文档组织、历史/回退/公开边界；解除开源下游阻塞 | D8 |

D4 与 D5 可在接口冻结后并行；D6 可与界面收尾并行。D3 的身份依赖复用首发的稳定身份与本机绑定工作，不重复建设身份发现。本项目文档归位 D7 不等于把所有会话产出公开到本仓库。

## 4. 迁移与公开边界

1. 先做只读清单：当前文档、被引用的历史内容、关联/证据、缺失正文和预期去向。不沿用会话中的文档数量估计。
2. dry-run 默认使用合成 fixture。读取或复制真实 store、导出正文、改登记/绑定、切换生效前，均需明确授权及一致性备份；不能在真实 store 上试错。
3. 由用户确认公开、私有、档案和不可恢复项的处置。拟公开设计/规范进入本项目 Git；敏感材料进入用户指定的私有项目仓库/档案去向，不自动公开、不以删除当前文件代替历史泄露检查。
4. 保留稳定登记和任务/计划关联，逐项核对旧证据内容映射。迁移后日常正文从工作区读取；兼容保留的内嵌内容明确标识为只读档案，不冒充已随 Git 管理的文档。
5. 代码能力与本项目文档归位都纳入开源前置验收。尚待授权的真实迁移不能标完成；不可恢复项不得悄悄略过，必须在人工门禁显式处理。
6. 真实迁移不授予合入、部署、重启、Git提交/推送或发布权限。用户手动执行主服务重启；完整验证在隔离候选完成。

## 5. 验收矩阵与门禁

| 场景 | 必须结果 |
|---|---|
| 新项目登记、外部编辑、刷新与重启 | 正文来自文件，无新正文 blob；关系/人工状态保留，读取不改rev |
| 文件变更、确认与再次变更 | 正常显示内容更新；打开不自动确认，确认基线可追溯 |
| 移动、删除、分支缺路径、根不可用 | 不丢登记/关联、不误删文件、不伪造原因或跨root补读 |
| 越界、junction/symlink、权限、类型、超限与读取中变化 | 安全拒绝、有界资源使用、错误分类准确，失败无写副作用 |
| 主工作区与并行worktree | 明确来源；会话不切共享根、不串内容；未支持上下文明示拒绝 |
| 固定证据后正文变化/切分支 | 可取回固定Git内容，审计固定来源；缺对象与hash不符区别表达 |
| 元数据并发、未知事件与旧代码 | 乐观锁有效；不静默误读外置语义，回放/快照/诊断一致 |
| 迁移重跑、中断、缺blob与恢复 | dry-run零写，正式迁移可恢复且不覆盖用户内容，历史映射不伪补 |
| 干净clone/安装与文档可移植性 | 文档正文随Git可读；没有看板数据时如实说明缺少管理状态 |
| 本项目公开面 | 拟公开材料归位、必要历史与资源可达、敏感数据和本机信息经过审核 |

实现涉及持久事件、证据和迁移，整体按 R3：专用分支/worktree、独立 home/workspace/board/认证，事前风险与代码/数据回退，合成测试、冻结候选、非实现者审查及人工验收。基线不改代码、不运行迁移/故障试验。

在实际候选提供的脚本上执行 npm run check:strict、npm run check:architecture、npm run build:client，并核对受影响工具/HTTP/宿主测试；check:strict 已含完整 npm test，不以离线 CI 代替宿主验证。构建可复现与冻结后门禁按[测试规范](<TESTING-POLICY.md>)执行。UI交互由人按清单验收，默认不新增浏览器自动化探针。命令须实际执行留证，本计划不声明通过。

## 6. 接入开源计划

开源交付与文档外置分别管理，以下工作保持各自归属。

- 首发决策包含“项目正文外置是首发前置，首发保持看板状态的用户级存储”。
- 身份任务等待首发决策与 D1 契约冻结，再为 D3 提供稳定身份/本机绑定；既有 file 证据根不被文档阅读上下文切换。
- 对外文档任务增加 D9 依赖，更新安装/演示/真实限制，覆盖外部编辑、确认基线、Git固定证据与迁移。
- 冻结候选任务与人工总闸直接增加 D9 依赖，不能只靠一句范围说明放行。
- 新增文档事件纳入现有 store 兼容门禁。

开源发布、公开推送、创建Release、npm publish仍需独立授权。任务人工审核通过不是发布授权。

## 7. 计划依赖

D1 → 首发身份 → D3。D9 → 对外文档、冻结候选与人工总闸。D1–D9 共九项任务，逐项保留人工审核。
