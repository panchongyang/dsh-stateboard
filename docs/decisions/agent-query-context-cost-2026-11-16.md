# Agent 查询累计上下文实测

日期：2026-11-16。测量实际共享 taskSummary、taskDetail 和 detailText，不是手写拟议摘要。输入为用户提供的完整任务查询记录；没有读取或执行证据指向的文件、测试或命令。

## 1. 口径

样本包含三条验收、六条证据、九条时间线、四个计划步骤和一份审查记录。完整紧凑 JSON 为 F；第一次 task 摘要为 S；第二次显式选择 audit 与一条 tests.log 证据记录为 R。两端 renderer 相同，结果文本字节相同。日志文件正文不在这次需求里。

单位为 UTF-8 字节，**不是模型 token、账单或延迟**。使用源样本真实内容计算，公开记录仅保留数值。旧 MCP 的 structuredContent 是否额外被宿主送模没有假定；F 只计一份完整数据。新 MCP 默认只返回共享文本，不再重复附全量 structuredContent。

## 2. 实测

| 内容 | UTF-8 字节 |
|---|---:|
| 用户格式化粘贴 | 23,164 |
| 一次完整紧凑 JSON F | 18,074 |
| 实际共享摘要 S | 2,898 |
| 实际审查 + 单条测试证据精读 R | 3,830 |
| 两次返回的正文合计 S+R | 6,728 |
| 两轮模型输入累计结果 2S+R | 9,626 |
| 已知目标直接精读 | 3,830 |
| 摘要后再完整读：返回合计 / 累计结果 | 20,972 / 23,870 |

相对于 F，返回正文合计减少 **62.8%**；把第一轮摘要重放也算上，累计结果减少 **46.7%**。摘要后再读全量会增加成本。

## 3. 公共前缀与调用参数

令 P 为每轮复用的系统提示、工具目录与已有聊天等公共输入前缀。一次为 P+F+Q1；两次为 2P+2S+R+2Q1+Q2。Q 是工具名及参数 JSON 的字节；不包含宿主消息包装、模型生成决策、推理或输出计费。

| 入口 | 一次，不含 P | 两次，不含 P | 两次获益的 P 上限 |
|---|---:|---:|---:|
| DSH 原生，省略 context | 18,162 | 9,978 | 8,184 |
| MCP，64 字符 context | 18,239 | 10,209 | 8,030 |

P=32 KiB 时，原生一次/两次为 50,930 / 75,514 字节；MCP 为 51,007 / 75,745 字节。此时两次读累计输入更大，即使工具结果明显更短。缓存可能改变计费，不能把这些字节换算成缓存命中或费用承诺。

## 4. 使用判断

- 仅需状态、版本、下一步：读摘要后停止。
- 已知需要审查与某类证据：直接选 sections 与证据过滤，一次精读。
- 先定位再决策：摘要后只读选中的 section，避免自动展开计划全文。
- 大段内容分页：使用 nextOffset 和 atRev，单列后续调用的累计成本。
- 需要完整内容：直接选择适当原文/知识读取，不机械先读一遍概要。

本记录证明该样本在给定读取目标下的上下文差异，不证明所有任务都节省 token，也不把一次读取记录算作重新运行测试。
