## 可交付能力

项目授权 MCP 通道新增 `search_project_knowledge` 和 `read_project_knowledge`，复用工作会话但不需要任务租约。前者交付原文碎片与已有关系，后者按稳定来源引用读取公开原记录或正文块。来源身份包含 commit、事件位置、版本和 hash 域；缺失、变化、覆盖缺口与分页失效分别表达。

第一层默认搜索 20 条，并在总条数内附带最多 10 条已有关系碎片。调用 Agent 可自由换关键词、跨概念继续查，不设累计轮数或跳转方向门禁。`discovery` 是调用者提出的线索，不保存为正式关系。自动关联为单次一跳，单次资源上限保护宿主，不裁决 Agent 的探索过程。

FTS5 contentless 派生索引按需追赶；SQLite 不可用或缓存故障时有界扫描降级。来源范围仅为留存记录、登记文档与证据引用。索引不归档外置正文，不进入 claim、submit、verify、快照或恢复的成功条件。精确回读直接校验来源，不依赖索引中曾有命中。

用法见[使用说明](../runbooks/projectboard-usage.md)，完整边界见[实施方案](../design/history-knowledge-read-model.md)与[CONTRACT §8.1](../CONTRACT.md#81-历史知识读取与检索)。

## 合成性能观测

样本为一个计划中的 250 个任务；首次查询后测 4 次热查询，再交替运行 12 个完整任务周期，每组 6 次。一个周期包含建任务、领取、begin、submit、verify。并发读取遇到来源发布竞争允许返回 `read-unstable`；全部 12 个写入周期成功。

| 指标 | 本次观测 |
|---|---:|
| 实际搜索引擎 | FTS5 |
| 冷查询 | 204.50 ms |
| 热查询中位数 | 131.33 ms |
| 无并发搜索的任务周期 P95 | 16.24 ms |
| 有并发搜索的任务周期 P95 | 14.26 ms |
| 并发查询 P95 | 142.97 ms |
| 事件循环 P95 | 29.80 ms |
| 进程峰值 RSS | 114.40 MiB |
| 派生缓存 | 684,032 bytes |
| 首次响应 | 33,074 bytes |
| 样本日志 | 563,825 bytes |

两组写入耗时的差异处于本次小样本波动范围，不能解释为检索使写入变快。该观测仅用于发现严重资源竞争，不构成容量或延迟 SLA。每次查询仍校验完整日志；64 MiB 源文件限制、30 秒请求期限和索引批次预算是当前资源边界，尚未证明上限附近的持续负载表现。

## 独立审查与修正

独立审查覆盖从基线到最终运行时代码的总体差异，并独立复验四个修正，针对性测试 4/4 通过：

1. 连续中文与英文接口名分开识别，FTS 与扫描均保留 `FTS5`、`restore_context` 的查询能力。
2. `docId@rev` 关系读取明确的历史版本；测试确实修改同一个文档，不用两个不同文档掩盖问题。
3. 关联正文不可读时返回 `relatedUnavailable` 与覆盖计数，不表现为没有关联。
4. 冷读启动后出现 writer 时，返回前再次校验发布前缀；未发布尾部拒绝交付，后续请求使不匹配缓存失效。

审查结论：候选 `68fb4b2` 无未解决阻断项；`87b4b8b` 仅修正工具目录测试预期，完整列表断言未放宽，独立审查结论保持通过。审查还核对了来源与 hash、重建与增量、来源变化、MCP 授权、worker 生命周期以及三个产品方针。

验证过程中还修正了离线 fixture 的 Git 上层目录干扰、缺少隔离开发依赖、测试注释规范和旧工具目录预期。前次失败未作为通过证据；最终严格门禁使用固定运行时代码与测试重新执行。
