## 决定

> 状态：已替代（现行语义见[实现契约](<../CONTRACT.md>)；正文保留方案或决策时的语境）。

按用户两条最高方针（1 不增加、应当降低心智负担；2 除 DSH 外零外部依赖并自动降级），对 D1 冻结契约里"固定证据"相关的两处措辞**予以复议并调整实现口径**：

- 原文[§4.2/§4.3](<../WORKSPACE-DOCUMENTS-CONTRACT.md>) 要求"首版每个项目只支持一个**显式获准**的 Git 内容仓库""正式取证要求调用者**显式确认**预期 commit/path/blobContentHash"。
- 调整为：**自动跟随、自动降级**，用户不再有单独的"批准仓库"与"确认固定版本"动作。

## 落地规则

1. **自动批准**：项目第一次需要固定证据时，由系统对主绑定根所在仓库自动记录批准（锚点 commit + objectFormat + bindingId），写一条可审计事件；不向用户索取任何输入。
2. **自动钉版本**：任务提交或人审通过时，若证据引用的文件**已提交且该路径工作区干净**，自动记录固定引用（commitOid / pathAtCommit / blobOid / objectFormat / blobContentHash），并在同一原子 commit 内携带匹配的 `doc/content-fixed`（契约 §5 屏障原样保留）。
3. **自动降级**（不报错、不弹窗、不要求安装）：
   - 无 git 或 git 不可用 → 证据停在"当前文件 hash"，界面小标记"当前文件（未固定）"；
   - 该路径有未提交修改 → 同样不钉版本（否则证明的就不是用户看到的内容），同样降级并标记；
   - 路径命中 filter/LFS/ident/working-tree-encoding 等无法安全还原的转换 → 降级并标记，不拒绝整条证据；
   - 非仓库、嵌套仓库、一个项目多个仓库 → 降级并标记。

## 保留不动的底线

- 不伪造：绝不把"未固定的当前文件"标成"已固定版本"；固定引用只在该版本字节与实际内容一致时生成。
- 已产生的固定引用不可变；`get_fixed` 回读仍按明确固定引用，未知 `fixed.v` 仍拒绝。
- 事件兼容与回退口径不变：新事件旧代码不可读，代码回退须配合 store 快照，RPO = 快照时点。

## 影响面
