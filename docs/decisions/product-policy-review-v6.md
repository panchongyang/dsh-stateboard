# 产品方针复查：审查治理 v6（硬切迁移偏离 + AI 审计信任标签）

日期：2026-11-02
依据：`docs/PRODUCT-PRINCIPLES.md`（现行产品方针）
对象：内部计划 v6、[审查治理 v6 设计草案](../design/review-governance-v6.md) rev 11

## 结论

设计符合面向**使用者**的方针一/二：旧门自动降级、不新增用户配置/审批、human verify 仍是一键、无外部依赖、迁移 fail-closed 不静默丢数据。需要澄清并登记的只有一件事：

**v2→v3 硬切迁移是开发者/发布准备的一次性负担，不是使用者的负担。** 外部新装用户没有 v2 数据，零操作；发布后使用者不承担迁移步骤。它不是面向使用者的功能偏离，而是发布工程口径，按「偏离登记」记录，避免以后误判成用户负担。

另外一点：**agent 审计报告是自述，不能显示成「已核验/已人审」**（不伪造底线）。UI 必须区分「人工审计」与「AI 审计（自述 + 证据 digest）」；`verifiedBy='agent'` 不得与 human 同标。

## 评审两问

1. 使用者是否需要先学会/先配置？——否。旧门自动降级，审计门就是原来的开关，无新配置；开发者需要一次性迁移（发布准备），不是使用者操作。
2. 失败会不会挡住使用者主流程？——否。没有独立 agent 时 human 仍可一键 verify；只有开发者发布前的 pre-release v2 store 在迁移前 fail-closed，这是为避免静默丢门的故意选择，登记为发布工程口径。

## 落实钩子

- **T2（schema v3）**：迁移脚本定位为开发者/发布准备步骤；`schema-migration-required` 文案 actionable、不暴露内部术语（「此项目由未发布版本创建，需要维护者升级数据；不要删除或重建项目」）；迁移脚本/测试不进包；偏离记录链接到任务。
- **T4（工具/看板）**：`lastAudit` 摘要标明 `by.kind`（human/agent）；agent 审计显示「AI 审计（自述）」而不是「已核验」。
- **T5（客户端/文档）**：Badge/抽屉/lastAudit 区分「人工审计」与「AI 审计（自述 + digest）」；不把 agent 审计显示成人工核验；无独立 agent 时 human 一键 verify 仍可用且不要求报告。
- **T6（集成验收）**：验收本复查的两问、偏离记录、`npm pack` 纯净；确认使用者没有新增配置/审批，迁移只落在开发者发布步骤。

## 偏离登记

- **性质**：开发者/发布准备的一次性硬切迁移，不是使用者功能流程。
- **范围**：仅本机 pre-release store；发布后新装用户无 v2 数据；迁移脚本不进发布包。
- **使用者零操作**：旧门自动降级、无新配置、human verify 一键、失败有 human fallback。
- **不偏离的底线**：不伪造审计强度；不静默丢数据；不因迁移失败删除/重建项目。
- **复议条件**：若未来出现外部 v2 store，重新评估是否提供随包迁移工具或回到运行时兼容。
