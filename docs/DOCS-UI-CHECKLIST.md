# 文档页（外置文档）人工验收清单

对应 [UI-REDESIGN.md §4.4](<UI-REDESIGN.md>)。「实际」列留空，由验收人填写（通过 / 失败 + 现象）。

## 0. 准备

- 在独立测试环境（见 [TEST-ENV.md](<TEST-ENV.md>)）或获准的候选实例里验收，不用真实 store。前端改动需要重启 dsh-web 并刷新页面后才生效（重启由用户执行）。
- 在测试项目的主工作区准备文件：`docs/ok.md`（几行 Markdown）、`docs/big.md`（超过 256 KiB 的文本，用来看截断；不超过 16 MiB）、`docs/notes.txt`、`docs/bad.txt`（写入非法 UTF-8 字节）、`docs/pic.png`（任意二进制）。另备一个文件放在绑定根目录之外。
- 如要验多工作树，项目需有第二个绑定（worktree）并在其中放同名文件。

## 1. 正常路径

| # | 步骤 | 预期 | 实际 |
|---|---|---|---|
| 1.1 | 打开「文档」页 | 列表同时有内嵌与外置文档，按目录分组（内嵌在「看板内嵌」组）；每条记录只出现一次；行里只有标题、日期、文件名和至多一个状态信号 | |
| 1.2 | 点「登记外置」，标题 `验收文档`，路径 `docs/ok.md`，bindingId 留空，勾选一个任务，登记 | 提示已登记，自动进入该文档详情；列表出现新行 | |
| 1.3 | 展开详情底部「技术详情与登记管理」→ 读取来源 | 显示绑定 id、绑定根目录（主工作区）、相对路径、「刚刚读取 · 观测于 …」；收起时默认视图里看不到这些字段 | |
| 1.4 | 查看状态 | 页头 meta 行显示管理=草稿；状态行分两段「可读」「未确认」；Git 实际状态在技术详情里；各维度分开，没有合并的“正常”标志 | |
| 1.5 | 查看正文预览 | `.md` 按 Markdown 渲染，「查看原文」可切换；标注「完整预览」；界面不出现内嵌 hash / size 字样 | |
| 1.6 | 点「确认当前内容」→「确认这个版本」 | 提示已确认；状态行变为「已确认，内容未变」并带确认时间；「确认当前内容」按钮消失；技术详情的「确认基线」出现 hash、确认时间、确认人；列表该行出现 ✓ | |
| 1.7 | 「编辑信息」改标题、把状态改为「评审中」保存 | 标题与 meta 行的管理状态更新；列表行出现小字「评审中」；确认情况保持不变 | |
| 1.8 | 点关联任务名 | 打开该任务抽屉；任务里的文档入口也能回到此文档 | |
| 1.9 | 在正文独占行引用相对 PNG/SVG（含根内 `../`），再引用缺失图片、非白名单扩展名与远程 URL | 合法图片正常显示且不溢出，alt 作说明；缺失/被拒绝图片回退原文本，不影响其余正文；非白名单不显示，远程 URL 不发图片请求 | |

## 2. 拒绝与冲突

| # | 步骤 | 预期 | 实际 |
|---|---|---|---|
| 2.1 | 登记路径填 `docs/nope.md`（不存在） | 被拒绝；说明目标须是绑定根内此刻存在的普通文件；表单保留输入 | |
| 2.2 | 登记路径填 `C:/x.md`、`/etc/x`、`a\b.md`、`a/../b.md` | 提交前即提示「不要写绝对路径」「请用 /」「不能有 ..」，不发请求 | |
| 2.3 | 登记指向根目录之外的文件（用 `..` 之外的符号链接或 junction） | 被拒绝，原因是越出根目录或安全拒绝，没有读取其内容 | |
| 2.4 | 登记时 bindingId 填 `bnd_bogus` | 提示绑定无效，让用户填有效 bindingId 或留空 | |
| 2.5 | 两个浏览器页打开同一文档；页 A「编辑信息」保存；页 B 随后保存 | 页 B 提示登记信息已被修改、需重新读取；有「重新读取」按钮；输入没有被自动重放 | |
| 2.6 | 打开详情→确认表单（不提交）→外部编辑文件内容→提交确认 | 被拒绝，提示内容在上次观测之后变了；点「重新读取」后看到新内容和新 hash，需再次确认 | |
| 2.7 | 对 `docs/big.md` 打开确认表单 | 预览被截断时必须先勾选「我知道只看到了部分正文…」才能提交 | |
| 2.8 | 从任务抽屉里点一个外置文档的入口 | 直接进入外置文档详情，不出现“请求失败”红条 | |
| 2.9 | 解除登记后看详情 | 灰色横幅说明已解除、文件未删、不能再修改；不再出现「编辑信息」「确认当前内容」「重定位」「解除登记」 | |
| 2.10 | 页 A 打开「编辑信息」表单（先不保存）；页 B 改同一文档并保存；页 A 点「重新读取文件」 | 页 A 表单自动关闭并提示“登记信息已变化…草稿没有提交”；不会用新版本覆盖页 B 的修改 | |
| 2.11 | 对 `docs/big.md` 打开确认表单并勾选知情；外部改文件内容后在页内点「重新读取文件」 | 确认表单自动关闭；重新打开后须重新勾选 | |
| 2.12 | 页 B 解除登记某文档；页 A 点列表刷新 | 页 A 该行立即划线、显示“已解除登记”并沉到本组末尾 | |
| 2.13 | 文件被改成缺失后只点列表刷新（等缓存过期，约 30 秒） | 该行信号更新为黄点“路径不存在”，计入「需处理」，不需要先点进详情 | |
| 2.14 | （需要特制服务端）外置列表返回 schemaVersion=2 | 列表顶部出现只读提示；「登记外置」及全部写入按钮禁用 | |
| 2.15 | 接上条：列表返回 2 后让外置列表请求失败（如暂停服务）再点列表刷新；随后恢复服务并刷新 | 失败刷新后仍是只读、登记与写入按钮仍禁用；恢复成功返回 1 后才可写 | |

## 3. 不可用态与预览

对每一行：制造条件 → 点「重新读取文件」。每一种都要确认：HTTP 不弹错误窗；横幅有可操作文案且带「重新读取文件 / 重定位… / 解除登记…」；标题、关联、管理状态仍显示，确认基线在技术详情里；文案不说“已删除 / 换了分支”。

| # | 条件 | 预期可用性标签 | 实际 |
|---|---|---|---|
| 3.1 | 重命名或移走已登记文件 | 路径不存在（文案声明无法判断原因，横幅里有「重新读取文件」「重定位…」「解除登记…」） | |
| 3.2 | 临时改名绑定根目录或让其不可达 | 根目录不可达 | |
| 3.3 | 重定位到一个已退役或不存在的绑定（经命令接口造出） | 绑定失效，提示用重定位 | |
| 3.4 | 去掉进程对文件的读取权限 | 无读取权限 | |
| 3.5 | 把文件换成指向根外的符号链接 | 越出工作区根 / 安全拒绝 | |
| 3.6 | 把文件换成同名目录 | 不是普通文件 | |
| 3.7 | 把文件扩到 16 MiB 以上 | 超过大小上限；没有预览；不出现确认按钮 | |
| 3.8 | 登记 `docs/bad.txt` | 非法 UTF-8；没有预览；不出现确认按钮 | |
| 3.9 | 登记 `docs/pic.png` | 格式不可预览；显示「不代表文件为空」的说明而不是空白；仍可确认 | |
| 3.10 | 正在持续写入的文件上观测 | 读取中变化，提示等写入结束 | |
| 3.11 | `docs/big.md`（超过 256 KiB 预览上限） | 正文上方有显著黄色提示：只显示前 N 字节、全文 M 字节、不能据此认为已读完；正文以原文显示 | |
| 3.12 | 不可用文档的列表行 | 行内显示标题、文件名和可用性短词（与详情一致）；「需处理」筛选能找到它 | |

## 4. 刷新与缓存

| # | 步骤 | 预期 | 实际 |
|---|---|---|---|
| 4.1 | 打开详情后 30 秒内再次进入同一文档 | 技术详情里观测时间显示「缓存结果」 | |
| 4.2 | 点「重新读取文件」 | 技术详情里显示「刚刚读取」，观测时间更新 | |
| 4.3 | 外部修改文件后只点「重新读取文件」，不点确认 | 状态行变为「确认后有改动」并出现主色横幅与「确认当前内容」；列表行出现“已改动”；基线 hash 不变；没有任何自动确认 | |
| 4.4 | 点列表右上的刷新按钮 | 列表重载；不触发确认；不丢失当前详情 | |
| 4.5 | 观测失败（例如暂停服务）后点「重试」 | 错误条显示失败原因，恢复后重试成功 | |
