# UI 2.0 规格说明

> 版本：v2 · 2026-10-22 · 适用：P1–P6（计划 ProjectBoard：MVP 交付 + UI 2.0 v3，步骤 s5）
> 设计背景见 [UI 重做设计](<../UI-REDESIGN.md>)，优先级口径见 [优先级语义](<../decisions/priority-semantics.md>)。
> 约束：浏览器半仍是**手写单文件、无构建、只 require('react')、禁 innerHTML**；不改 core 状态机 / HTTP 路由 / 命令信封 / 数据格式。

---

## 0. 一句话目标

把「12 档字号 + 26/30px 控件 + 只有窄屏断点 + 24 个控件平铺」换成
**「7 档字号 + 3 档控件 + 双向响应式 + 一屏一个主操作 + 列表/看板双视图」**。

三组判据（最终验收也用这三条）：可读（对比度 ≥4.5、正文 14）、可点（控件 ≥32）、可聚焦（每屏 1 个 filled primary）。

## 1. 类型刻度（7 档，基准 14）

| token | px | 行高 | 字重 | 用途 | 替换掉 |
|---|---|---|---|---|---|
| `--pb-fs-xs` | 11 | 1.45 | 500 | id / hash / 时间戳 / 计数 | 10、10.5 |
| `--pb-fs-sm` | 12 | 1.5 | 500 | badge、chip、列表元信息、字段 hint | 11、11.5、12.5（部分） |
| `--pb-fs-md` | 13 | 1.5 | 500 | 控件文字、按钮、字段 label、tab | 12、12.5（部分） |
| `--pb-fs-base` | **14** | 1.6 | 400 | 正文、卡片标题、描述、列表项 | 13（根字号） |
| `--pb-fs-lg` | 16 | 1.4 | 650 | 区块标题、抽屉标题、计划步骤标题 | 15 |
| `--pb-fs-xl` | 20 | 1.3 | 650 | 页面标题（项目板 / 系统健康 / 计划标题） | 15（品牌） |
| `--pb-fs-num` | 28 | 1.15 | 650 | 统计数字，tabular-nums | 22 |

规则：

1. **删除所有 .5 档**（10.5 / 11.5 / 12.5），只允许上表 7 个值；新增文字一律用 token，不写字面量。
2. **中文不用 `text-transform: uppercase` 与 `letter-spacing`**：对汉字无效，只会让它更小更灰（现 `.pb-section__title`、`.pb-drawer__eyebrow`、`.pb-attention__head` 三处）。
3. 文档正文 `.pb-md` 保留 16px/1.9；它的**外围**（列表、工具栏、状态行）从 10.5–12.5 升到 12–14，两套字号不再差 3px 以上。
4. id / hash 这类机器标识统一走 `.pb-mono` + `--pb-fs-xs`，并且**只出现在抽屉与健康页**，卡片上不再出现（见 §9）。
5. 数字统一 `font-variant-numeric: tabular-nums`（轮询刷新不抖动）。

**P1 验收口径**：统计 `lib/client.js` 样式表里 `font-size` 声明 → 去重后恰好 7 个值；≤12.5px 的声明占比从 84% 降到 ≤25%。

## 2. 控件尺寸（3 档，一个变量）

| token | 高 | 用途 |
|---|---|---|
| `--pb-control-sm` | 32 | 表格内、卡片内联动作、工具卡 |
| `--pb-control-md` | **36** | 默认按钮 / 输入 / select / 图标按钮 / tab |
| `--pb-control-lg` | 40 | 抽屉主操作、底部确认 |

| 组件 | 现状 | 目标 |
|---|---|---|
| `.pb-btn` | 30 / 字 12 | **36** / 字 13 / padding 0 14 |
| `.pb-btn--sm` | 26 / 字 11.5 | **32** / 字 12.5 / padding 0 11 |
| `.pb-input` `.pb-select` | 30 / 字 12.5 | **36** / 字 13.5 / 圆角 8 |
| `.pb-btn--icon` | 30（sm 26） | 36（sm 32），图标 16–18 |
| `.pb-chip` | ≈21 / 字 11.5 | **30** / 字 12.5 / padding 0 11 |
| `.pb-badge` | 18 / 字 10 | **22** / 字 12 / padding 0 8 |
| `.pb-switch` | 34×20，拇指 14 | **40×24**，拇指 18，位移 16 |
| `.pb-tab` | ≈27 / 字 12.5 | 36 / 字 13 |
| `.pb-search` | 30（compact 28） | 36（compact 32） |

规则：

1. **输入与按钮同高**：都读 `--pb-control-*`，不允许出现「26px 按钮配 30px 输入」。
2. 同一行的按钮与字段用 `align-items: center`（不是 `end`）：底对齐会让 26 vs 36 的差变成可见的 10px 错位。
3. 按钮放进表单时**不进入 grid 的字段列**：字段与动作分开两块，动作用 `justify-content: flex-end` 对齐右缘。
4. 可点元素最小命中区 32×32（图标按钮、chip、关闭）。

## 3. 间距 / 圆角 / 阴影

- 间距只允许 **4 / 8 / 12 / 16 / 20 / 24 / 32 / 40**；删除 6 / 7 / 9 / 10 / 14（现在 gap 有 5 种不在网格上）。
- 页面内边距 24（宽屏 32）；区块内 16；区块间 16；卡片内 16；行间 8。
- 圆角三档：**8**（控件）/ **12**（卡片、区块、列）/ **16**（抽屉、面板）；删除 6 / 10 / 14 / 20 与 JS 内联的 8。
- 阴影两档保持（卡片 hover、抽屉），暗色另调；不再给每个区块描边——**同一层只用一种分隔手段**（线或底色，不叠加）。

## 4. 颜色与对比度（硬指标）

| token | 亮色 | 暗色 | 对比度（亮底） | 用途 |
|---|---|---|---|---|
| `--pb-text` | #0f1115 | #f9fafb | 17.0 | 主文本 |
| `--pb-text-2` | #61666b | #cfd3d6 | 5.80 | 次要文本 |
| `--pb-text-3` | **#6b7280**（原 #979da6） | #9ca3af | **4.63**（原 2.61 ✗） | 元信息、hint、计数 |
| `--pb-accent-text` | **#2f5bc7** | #7aaaff | **6.10** | 文字用主色（填充仍用 `--pb-accent`） |
| `--pb-warn-text` | **#b45309** | #fbbf24 | **5.02** | 警告 badge 文字 |
| `--pb-success-text` | **#15803d** | #4ed17e | **5.02** | 通过 / 完成 badge 文字 |
| `--pb-violet-text` | **#6d28d9** | #b3a1ff | **7.10** | 评审中 badge 文字 |

规则：

1. **淡底 + 同色文字**必须实测 ≥4.5:1；不够就用 `-text` 变体（badge 背景仍用 `color-mix(<色> 10%, transparent)`）。
2. **状态色只出现在点、badge、细条、左边条**，不做整块底色（attention 卡除外）。
3. **禁止内联颜色**：所有颜色走 token；需要新色先补 token（暗色也要补）。现存的 `--pb-accent-soft` / `--pb-accent-border` 是**未定义 token**，暗色下关联文档 chip 的对比度是 **1.06:1**（文字隐形）——P1 修。
4. 一屏内同时只允许一种强调色（accent）；warn/violet/success 只做状态标记。

## 5. 焦点梯（一屏一个主操作）

| 层级 | 规则 |
|---|---|
| 页面 | 每页最多 1 个 filled primary。列表/看板 = 「新建任务」；「新建项目」降为 secondary |
| 全局 | 页头固定「下一个：#1 · P150 · 标题」一条，点击开抽屉（优先级可视化见决策文档） |
| 抽屉 | sticky「下一步」条 = **当前状态唯一主操作** + 一句原因（来自 `allowedOps[].reason`）；其余进「更多操作 ▾」 |
| 危险操作 | 驳回 / 取消 / 重开只在「更多」里，分组在「危险」，不与主操作同排 |
| 主操作推导 | 由 `task.state` 推导，不按 op 数组顺序：ready→claim；in_progress→submit；review→verify（次：reject）；blocked→unblock；interrupted→reconcile |
| 不可用 | 禁用 + `title` + 行内 hint 说明原因，不隐藏（隐藏会让人以为坏了） |

现缺陷：`topOps = enabledOps.slice(0,3)`（lib/client.js:1476-1483）按 op 名取前三个，primary 也按 op 名判定 → 主操作可能不是当前状态该做的那件事。

## 6. 动效（3 档时长 / 2 条缓动）

| token | 时长 | 缓动 | 用在哪 |
|---|---|---|---|
| `--pb-d-1` | 120ms | `cubic-bezier(.2,0,0,1)` | hover / press / focus ring |
| `--pb-d-2` | 180ms | 同上 | 展开收起、toast、页签内容、视图切换、更新提示 |
| `--pb-d-3` | 240ms | `cubic-bezier(.16,1,.3,1)` | 抽屉 / 面板进出 |

必做（当前**一个都没有**）：

1. 抽屉**退场**：opacity + translateX(12px)，160ms（现在直接卸载，界面"啪"一下没了）。
2. 页签与**视图切换**：8px 位移 + 淡入 180ms，方向随切换顺序。
3. 表单展开：`grid-template-rows: 0fr → 1fr` + opacity，180ms（不要 animate height）。
4. toast 进场/退场各 180ms；栈内新增时其余项位移 120ms。
5. 轮询更新：变化的数字做一次 300ms 背景闪（只改背景，不位移、不缩放）。
6. 按下态：`transform: scale(.98)`，120ms；卡片 hover 从 `translateY(-1px)` 改为 `translateY(-2px)` + 阴影加深。
7. 列表进场：stagger 20ms × 最多 5 项（再多不再延迟）。
8. `prefers-reduced-motion: reduce` 下全部归零（现有逻辑保留，新增动画同样受控）。

## 7. 响应式（双向，按容器宽度）

现有断点只有 `max-width: 1100 / 900 / 640 / 430`（四个），**没有 min-width**，也没有内容上限。

| 容器宽 | 布局 |
|---|---|
| <520 | 单列；抽屉全宽；看板列横滑 88%；列表隐藏次要列 |
| 520–900 | 统计 2 列；看板列横滑 78%；抽屉全宽；文档列表/编辑器互斥 |
| 900–1200 | 看板 5 列（≥230px）；统计 3+2（**不得留空行**） |
| 1200–1680 | 看板 5 列（270–320）；统计一行 |
| ≥1680 | **内容封顶 1680 居中**；列宽 ≤340；统计块 ≤240；抽屉 640 |

规则：

1. 封顶加在**页面容器**（`.pb-main > *` 或统一 `.pb-page`），不是给每个区块加。
2. 宽屏加的是**留白与列宽上限**，不是把卡片拉到 500px 空框。
3. 抽屉：`<900` 100%，`≥900` 560，`≥1680` 640。
4. 修 900 宽统计块掉行：`grid-template-columns: repeat(auto-fit, minmax(140px, 1fr))` + `.pb-stat--wide` 在窄档取消 span 2。

### 7.5 视图层（列表 / 看板）

同一份 board 数据两种投影；共享搜索、筛选、抽屉、2s 刷新节奏；切换写 `localStorage['projectBoard.view'] = 'list' | 'board'`（默认 list）。

| | 列表 | 看板 |
|---|---|---|
| 回答 | 「我现在该做哪件」 | 「系统什么状态、有多少在跑」 |
| 排序 | 按状态分组，组内按优先级；可切「最近更新」 | 列内按优先级 |
| 折叠 | 「已完成」默认折叠成一行 | 完成列默认折叠；空列 ≤120px 窄条 |
| 行/卡 | 行高 44：状态点 · 标题（单行截断）· 优先级 · 验收 x/y · 人审 · 相对时间 | 两行卡片：标题（2 行截断）+ 一行 meta |
| 滚动 | 页面滚动 | **列内滚动**，列头粘住，页面不整体滚动 |

键盘：↑↓ 移动、Enter 开抽屉、`/` 聚焦搜索（沿用现有）。

## 8. 任务抽屉（P3 核心）

### 8.1 目标结构

~~~text
┌ 头（sticky）─────────────────────────────────┐
│ ● 进行中  修订 7                        [×]  │
│ UI 全面重做：现代视觉 + 交互组件重构           │ 16px/650
│ P200 · 权重 1 · 会话 …10                       │ 12px 元信息，最多两段
├ 下一步（sticky，唯一主操作）─────────────────────┤
│ 下一步：提交证据   [提交证据]  [更多 ▾]         │
├ 概览（只读）───────────────────────────────────┤
│ 描述 14/1.7                                    │
│ 验收 2/3  ▓▓▓░░   ✓… ✓… ○…                    │
│ 证据 2    [文档 doc_…] [文件 lib/client.js]    │
│ 关联 1 篇 · 计划 v1 ▸（折叠一行，0 篇时不渲染）  │
├ 操作（按需展开，同时只开一个）────────────────────┤
│ ▸ 提交证据（单列表单，确认后收起）              │
│ ▸ 治理：人审 / 阻塞 / 对账 / 危险操作           │
├ 时间线（折叠，最近 5 条 ▸）──────────────────────┤
└ 底栏：仅在有未保存输入时出现「取消 / 确认」───────┘
~~~

### 8.2 规则

1. **24 个控件 → 首屏 0 个**：表单不常驻，点主操作或「▸」展开，Esc 收起，同时只开一个。
2. **消灭同名不同义**：顶部只有「主操作 + 更多」，不再放会 `scrollIntoView` 的「开始/提交/阻塞」（现在同名两处、行为不同）。
3. **读写分区**：概览全只读，操作区全可写且有边界，不混排。
4. **空区块不渲染**：关联资产 0 篇、证据 0 条、时间线 0 条时不出现空卡片（改为 meta 行里一句）。
5. **表单单列**：`<720` 一格一行（label 左上、控件满宽、动作右对齐 36px）；`≥720` 最多两列。`select` 选项文字截断 24 字，全文进 `title`。
6. **下拉指示符**：`IconChevron` 旋转 90°（现在是右箭头 `>`，像"下一级"）。
7. **危险操作**只在「更多 → 危险」里，带二次确认文案。
8. **底部栏不再独占一行放「关闭」**：关闭移到头部 ×；底栏只在有未保存输入时出现。
9. **元信息去重**：id 只出现在 meta 行（12px mono）；P/权重/会话保留；令牌只在有租约时显示。
10. 焦点：打开时焦点进标题区，Esc 归还到原卡片；展开表单时焦点进第一个字段。

### 8.3 状态 → 主操作映射（唯一真源）

| state | 主操作 | 次操作（进「更多」） | 说明文案来源 |
|---|---|---|---|
| backlog | 就绪（ready） | — | 「依赖未满足：…」 |
| ready | 领取（claim） | — | 「领取后开始写意图」 |
| in_progress | 提交证据（submit） | 释放租约 / 标记阻塞 | 「写意图 → 提交」 |
| review | 通过（verify） | 驳回（reject） | 「等人审 / 自动验证」 |
| blocked | 解除阻塞（unblock） | — | blocker 原因 |
| interrupted | 对账（reconcile） | — | 上次意图摘要 |

## 9. 看板与卡片（P6）

1. 统计块 **6 → 4**（就绪 / 进行中 / 评审 / 待我处理），完成度移进页头细条（不占一格）；列头已有计数后，顶部不再重复报数。

## 11. 验收怎么做

| 层 | 做法 |
|---|---|
| 纯逻辑 | `test/client-smoke.mjs`：`nextActionFor`、`priorityRanks`、密度解析、视图持久化、样式表统计（字号档数/控件尺寸档数）、命令白名单冻结 |
| 视觉 | 在隔离宿主用合成项目检查 560 / 900 / 1440 / 1920 / 2560 宽度及亮暗主题。 |
| 人工 | 按 §1–§9 点检操作、响应式布局及主题。 |

**截图命令必须带 `--force-prefers-reduced-motion`**，否则抽屉入场动画会被截在半透明状态（假 bug）。

机器可断言的指标：

- 字号去重 = 7；≤12.5px 占比 ≤25%
- 控件高度去重 = 3（32/36/40）
- 文本/背景组合对比度 ≥4.5:1（枚举 token 对）
- 抽屉首屏可交互元素 ≤3
- 2560 宽下列宽 ≤340、内容宽 ≤1680
- 同任务在两视图中的 rank 一致

## 12. 非目标（本轮不做）

- 拖拽排序、SSE 推送、移动端独立路由
- 引入组件库 / 构建链 / 新依赖
- 文档正文渲染（表格、图表、链接）—— 由文档渲染那组任务负责
- 主题体系重做（只修对比度与缺失 token）
- **不改 priority 的数值语义**（core 的排序与派发逻辑不动，UI 只做 rank 投影）
