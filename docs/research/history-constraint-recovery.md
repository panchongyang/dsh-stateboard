# 历史知识检索与约束恢复技术调研

> 状态：技术调研归档；候选架构、选型与实验建议待讨论，未定案。
> 调研日期：2026-11-13。代码基线：`665da1d`。
> 产品方向与下阶段唯一目标以[方向记录](../decisions/structured-continuous-knowledge-base.md)为准。

## 调研结论与范围

Project Board 已有较好的事实留痕基础，但在本次调研基线上，还不能直接提供可靠的历史约束恢复。主要缺口是外部 Agent 缺少检索和完整来源读取接口，以及“谁记录了什么”已有结构，而“某项决定现在是否适用、被什么取代”尚未统一表达。后一个问题不能单靠提升检索相关性解决。

调研提出的最小验证候选是“带来源与版本信息的全文检索，加上现有关联扩展”。独立约束实体、向量数据库和 GraphRAG 的必要性，应由实际失败样本决定。这是后续方案讨论的一项建议，不是已采纳架构。

调查覆盖仓库代码、契约、设计文档、实际 MCP 读取响应和官方技术资料。现状结论对应上述代码基线；组件成本比较是工程判断，实验指标是建议，未形成性能或检索质量实测结果。

## 当前能力与可复用基础

### 已有信息与来源

| 信息 | 已有结构与来源 | 可以支持的恢复及其边界 |
|---|---|---|
| 任务 | 标题、描述、验收项、标签、依赖、计划归属、修订号、提交与验收记录 | 恢复任务要求、执行关系和交付记录；任务完成不代表其中所有设计意见永久有效 |
| 计划 | `planHeads` 管理当前状态，`plans[id@version]` 保存版本，任务通过 `planRef` 关联 | 定位任务所属计划版本；计划版本变化不自动表达设计约束的废止 |
| 事件日志 | commit 包含 `seq/prev/hash/at/actor/cmdId/events`，事件承载实体数据 | 追溯来源、顺序和历史状态；Agent 陈述仍只是被记录的陈述 |
| 内嵌文档档案 | 修订号、正文 hash、内容寻址 blob | 精确引用已保留的旧正文；当前写入默认禁用，不是未来知识写入的默认入口 |
| 外置文档 | 稳定 `docId`、定位信息、管理状态、确认基线、任务和计划关联 | 提供身份和来源基础；`metaRev` 不是正文版本，正文变化可以不产生看板事件 |
| 证据与审查 | `acceptanceId`、来源、hash、`producedBy`、固定内容引用、`supersededBy`、`lastAudit`、`scopeDigest` | 核对材料和验收范围；不证明结论正确或某条规则仍有效 |
| 会话接续 | checkpoint 和 handoff 的 `note/nextActions`，digest 中的最近 checkpoint、验收记录和焦点计划 | 恢复少量交接信息；不是完整聊天记录或完整设计讨论档案 |

实现依据：[实体投影](../../lib/core/model.js)、[任务与关联文档视图](../../lib/core/views.js)、[存储契约](../CONTRACT.md)、[外置文档记录](../EXTERNAL-DOCS.md)、[证据替代处理](../../lib/core/evidence.js)、[审查范围指纹](../../lib/core/audit.js)、[会话记录](../../lib/core/commands/session.js)。

现有关联包括 `task.deps`、`task.planRef`、`doc.links.taskIds/planRefs` 和证据到验收项的关联，可以直接用于有界关系扩展。[normalizeDocLinks](../../lib/core/normalize.js)校验任务和计划版本引用，[docsForTask](../../lib/core/views.js)在读取时派生任务侧关联，避免重复维护双向数据。

看板记录可用 commit 序号和事件位置定位；正文可用修订号、hash 或固定 Git 身份定位。这为原文核对提供了基础。但没有保存到任务、文档、证据或 checkpoint 的讨论，检索系统无法可靠恢复。

### 已有搜索与未实现能力

- **任务列表**：前端对标题、ID、标签、负责人、计划 ID 和阻塞文本做字符串包含匹配，不搜索完整历史。见 [cardHaystack 和 filterCards](../../src/client/model/filters.ts)。
- **文档列表**：搜索元数据，并按需读取内嵌正文；外置正文不走这条正文搜索路径。见 [useInlineBodies 和 filterRows](../../src/client/pages/doc-list.tsx)。
- **事件读取**：`eventsView` 按 `after` 过滤后取末尾若干条，最多 500 条，不提供全文排名、实体历史查询或通用时点查询。见 [views.js](../../lib/core/views.js)。
- **任务时间线**：取该任务最近 30 条。采用快照冷开时，timeline 可能只包含快照尾部事件，不能当完整历史语料入口；完整 commit 集合另行保留。见 [JsonlStore 载入](../../lib/core/store.js)和 [taskView](../../lib/core/views.js)。
- 基线代码中未发现服务端全文倒排索引、BM25、Embedding、向量检索或 Reranking 实现。固定内容引用索引等领域索引不等于全文检索索引。

[查询模块 v2 规格](../specs/query-module-v2.md)文首写明实现未开始，其目标是浏览器端 WHERE 谓词。历史实体索引、`/history` 和 `asOf` 是另一项能力；调研时对应任务为待实施状态，当前 [handle.query](../../lib/core/handle.js)没有这些入口。设计文档出现接口名称不能证明能力已经存在。

### 外部 MCP 的能力边界

基线的 MCP 读工具是 `list_projects`、`list_tasks`、`get_task`、`get_work_context`。`get_task` 返回描述、验收项和证据计数；`get_work_context` 再增加阻塞信息、阶段提示和下一动作。它们没有返回完整证据、关联文档、审查报告或事件原文，也没有搜索参数。长字段裁剪后标记 `truncated`。见[工具定义](../../lib/host/mcp-tools.js)和[返回投影](../../lib/core/project-reader-projection.js)。

因此，外部 Agent 即使找到正确任务，也可能只知道有几条证据，无法继续核对这些证据支持了什么。DSH 原生工具或 HTTP 的读取能力不能直接算作外部 MCP 已有能力。

现有只读架构可以复用：优先读 writer 已发布状态，冷读取放在 worker，不领取任务、不修日志、不续租。见 [createProjectReader](../../lib/core/project-reader.js)与[冷读 worker](../../lib/core/project-reader-worker.js)。

### 历史与当前事实的关系

需要分别表达三个层次：

1. **持久化事实**：某人在某次操作中提交、批准或记录了某项内容。
2. **当前投影**：按事件回放得到的任务状态、计划头和文档元数据。
3. **当前外部内容与现实状态**：工作区文件、Git 对象、部署结果等，需要另外观测。

事件日志使第一层可追溯并生成第二层，不自动证明第三层。hash 链支持完整性检查，也不等于对记录内容真实性的签名背书。

外置文档的管理状态、内容确认情况、可用性和 Git 状态相互独立。`adopted` 文档编辑后仍可保持 `adopted`，不能把“已采纳文档的当前正文”直接理解成“已批准的这份字节”。见[外置文档四维状态](../WORKSPACE-DOCUMENTS-CONTRACT.md)。

可以在不新增任务、计划、事件或证据核心实体的情况下建立检索，但仍需新增读取契约、来源抽取与派生索引。现有字段不足以可靠计算所有约束的有效性。

## 成熟技术与组件比较

BM25 是词法排序算法，Embedding 是语义表示，RAG 是检索结果参与生成的流程。它们都不直接提供项目事实权威性或约束有效性。下表按本项目单机、Node 和低外部依赖目标比较，成本是相对工程判断。

| 方案与组件 | 检索能力 | 增量更新 | 资源、维护与侵入程度 |
|---|---|---|---|
| SQLite FTS5 和 BM25 | 术语、错误码、接口名和精确关键词检索；支持字段权重和片段 | 支持增删更新，JSONL 到索引的同步需适配 | 嵌入式、可持久化、无独立服务；需处理中文分词和 Node 兼容性。[官方文档](https://www.sqlite.org/fts5.html) |
| MiniSearch 和 BM25+ | 纯 JS 全文检索、字段加权、前缀、模糊匹配和自定义分词 | 支持动态增删 | 接入较轻、无传递依赖；索引驻内存，适合中小语料验证，但仍是新增工程依赖。[文档](https://lucaong.github.io/minisearch/)、[设计](https://github.com/lucaong/minisearch/blob/master/DESIGN_DOCUMENT.md) |
| Embedding 与 Orama | 全文、向量和混合检索，补充同义表达和间接描述 | 文档变化后更新对应索引和向量 | JS 技术栈接近现项目；模型生成、推理和重建另有成本。[项目](https://github.com/oramasearch/orama) |
| Qdrant | 向量、过滤、混合与多阶段检索 | 支持持续更新 | 适合规模或查询压力增长后的独立服务；额外运维与当前开箱即用方针不匹配。[文档](https://qdrant.tech/documentation/hybrid-queries/) |
| sqlite-vec | SQLite 内的向量存储与检索 | 可以更新向量记录 | 比独立服务轻，但需原生扩展和模型；项目仍标注 pre-v1，应计入接口变化成本。[项目](https://github.com/asg017/sqlite-vec) |
| Hybrid 与 Reranking | 合并词法与语义候选，再对少量候选重排 | 底层索引更新；重排逐查询进行 | RRF 避免直接混加不同量纲分数；Cross-Encoder 增加推理延迟，无法找回未进入候选集的材料。[融合](https://qdrant.tech/documentation/hybrid-queries/)、[重排](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/) |
| 现有关联的结构化查询 | 精确寻找依赖、计划、关联文档和验收证据 | 从指定读取水位查询关系 | 成本低、可解释；不能凭空发现未登记关系，现有数据足够支持第一轮实验 |
| Microsoft GraphRAG | 抽取实体、关系和社区摘要，支持跨文档综合问题 | 更新涉及抽取结果和派生图结构 | 抽取、摘要和图维护成本高；生成关系不等于批准关系。调研时官方注明主要处于维护模式，并提示索引成本可能较高。[数据流](https://microsoft.github.io/graphrag/index/default_dataflow/)、[项目](https://github.com/microsoft/graphrag) |

### 中文与运行时适配

中文检索需要单独验证。FTS5 默认 `unicode61` 不做中文词语分割；trigram 支持子串，但少于三个 Unicode 字符的全文查询不匹配。“回滚”“租约”等短词不能遗漏。实验应比较中文分词、字符 n-gram 和精确标识符通道，并保留 `doc/content-fixed`、`requiresAudit` 等完整标识符。见 [FTS5 分词规则](https://www.sqlite.org/fts5.html#tokenizers)。

[package.json](../../package.json)声明 Node `>=22`，而 `node:sqlite` 从 22.5 加入，22.13 才不再要求实验开关；Node 22 的 `DatabaseSync` 同步执行。不能假设全部支持环境直接可用，也不宜放进宿主主线程。[Node 22 文档](https://nodejs.org/docs/latest-v22.x/api/sqlite.html)。[贡献指南](../CONTRIBUTING.md)另列 DSH 宿主的 Node 要求，插件引擎下限与宿主支持矩阵须分别核对。

语义检索需要对中文、英文标识符和否定句做专门评估。模型能识别“相关”不代表能区分“允许”和“禁止”，也不自动判断某条旧约束是否已经失效。小规模语料可以先比较精确向量扫描，不因使用 Embedding 就引入独立向量数据库。

|---|---|---|

## 历史约束恢复的主要难点

### 相关性、权威性与有效性

| 维度 | 回答的问题 | 可利用的信号 |
|---|---|---|
| 检索相关性 | 是否涉及当前问题 | 词法与语义分数、重排、直接关联 |
| 事实权威性 | 谁作出的什么记录，依据是什么 | 原文、actor、明确批准记录、文档角色、证据身份 |
| 约束有效性 | 是否适用于当前项目、版本、模块和操作 | 明确适用范围、替代或例外声明、内容版本、目标基线 |

三项不能合成一个“可信度”分数。来源可追溯不等于当前适用，检索分数高不等于有权作出决定。[验收契约](../CONTRACT.md)明确说明报告与指纹不证明内容正确，Agent 报告属于自述。

### 本仓库中的真实误读案例

**固定证据**：[冻结契约](../WORKSPACE-DOCUMENTS-CONTRACT.md)要求显式确认，[后续复议](../decisions/auto-follow-fixed-evidence.md)调整为自动跟随和自动降级；[当前实现说明](../DOC-EXTERNAL-EVIDENCE.md)还明确 `verify` 不重新钉版本。需要找齐原规则、变更依据和当前口径，并核对操作时点。

**Agent 验收权限**：历史已完成任务保存较早的独立审计要求；当前普通任务允许具有项目权限的 Agent 显式验收，审计门才要求独立性。旧任务的 `done` 状态不能让旧验收文本成为当前全局约束。见[现行契约](../CONTRACT.md)与 [verificationRoleProblem](../../lib/core/audit.js)。

**历史查询**：规格中出现 `/history`、`asOf` 和索引规则，不代表接口已经实现。检索结果须保留方案状态与实现依据。

“最新记录优先”“已完成任务优先”“decision 文档优先”只能作线索，不能成为统一裁决规则。代码行为与文档要求不一致时，也应呈现差异，不能自动用其中一方改写另一方的权威性。

### 替代、范围与继承

现有 `supersededBy` 表示证据替换，不表示设计决策废止；计划新版本也不等于所有旧约束失效。最小方案可遵循以下表达边界：

- 有明确替代声明，展示新旧来源和被替代范围；只有标题相似、时间较新或内容冲突时，保留“可能冲突，待判断”。
- 任务依赖表示执行依赖，不能自动解释成约束继承；文档关联任务也不能自动解释成正式批准输入。
- 项目规则、模块规则、版本限定和局部例外分别表达；局部例外不能静默覆盖更高层规则。
- 记录时间不一定是生效时间；缺少明确生效版本时，不从时间戳推导。
- 文档可能只有某一条款被替代，不能因局部变化把整份文档宣布失效。

### 没有命中与确认不存在

| 情况 | 可得出的结论 |
|---|---|
| 指定语料和查询条件下没有命中 | 本次没有检索到 |
| 索引落后、来源不可读、语料未纳入或结果截断 | 覆盖不足，不能据此判断 |
| 有权来源明确声明某范围没有额外限制 | 可以引用这项有范围的否定声明 |
| 历史记录冲突，无法确定覆盖关系 | 存在待解决冲突 |

即使索引完整、查询成功，也不能证明自然语言查询穷尽了所有相关约束。

### 跨模块发现与上下文干扰

低成本发现路径可以组合任务术语检索、依赖和计划扩展、关联文档读取，以及命中文档明确引用的一至两跳扩展。本仓库已有 [AGENTS.md](../../AGENTS.md)和[文档地图](../INDEX.md)可作规范入口；通用产品不能把具体文件名硬编码成所有项目的规则。

语义检索可补充措辞不同的候选，但同模块、相似路径和共同关键词只是相关线索。Agent 应核对适用性，结果正文作为引用数据，不能改变 Agent 的权限和工具规则。

控制干扰需要按来源和版本去重，保留章节上下文与例外条件，限制单次候选和总 Token，并允许按引用展开。摘要可帮助导航，但不能代替原文，也不能自动作为批准事实写回。

### 额外结构化的收益

| 层次 | 维护负担 | 收益 |
|---|---|---|
| 原文加来源、状态和版本 | 最低 | 先验证检索与来源恢复是否有用 |
| 既有决策文档上表达范围、替代对象和批准依据 | 中等 | 机械识别部分覆盖关系 |
| 独立约束实体及生命周期和继承规则 | 高 | 更精细管理，但增加产品责任和同步负担 |

现有数据足以支持第一层。只有反复出现“找到原文，却缺少覆盖或范围声明”的失败，才有证据推动第二层；不能预设第三层必要。

## 候选架构与集成方式

### 三种候选

| 方案 | 组成 | 核心模型变化 | 主要取舍 |
|---|---|---|---|
| A 原文检索与来源恢复 | 词法索引、来源定位、现有关联查询、预算控制、原文回读 | 无须新增领域实体 | 最低侵入；同义召回和隐含适用性仍有限 |
| B 可选混合检索 | A 加 Embedding 通道、结果融合及必要重排 | 不必改变任务、计划与证据模型 | 补充间接表达；增加模型、资源、更新和降级成本 |
| C 文档级决策声明 | A 加明确的范围、替代与批准引用 | 可能需要少量元数据契约 | 改善有效性判断；需确定维护、批准和部分覆盖语义 |

同义表达漏召回可验证 B，范围和替代关系不清可评估 C。GraphRAG 尚无足够必要性证据。这些候选不构成必须依次执行的建设路线。

### 职责与数据流

```text
看板日志、文档登记及获准正文
    → 只读来源适配
    → 隔离的检索索引
    → MCP 搜索与原文读取
    → Agent 理解材料、核对适用性并执行

AgentWorkflow 管理调用时机和流程门禁
外部 Agent 可以直接调用 MCP，不依赖 AgentWorkflow
```

### MCP 最小表面候选

| 候选工具名 | 用途 | 关键返回 |
|---|---|---|
| `search_project_context` | 按项目、查询及可选任务定位材料 | 短原文、命中原因、来源引用、记录状态、读取水位、覆盖不足 |
| `read_project_sources` | 按返回引用展开原文或历史版本 | 内容身份、上下文、来源变化、缺失或截断 |

返回信息可分为定位、内容身份、来源事实、检索信息、覆盖情况五部分。任务修订、正文 hash、固定 Git 引用分别保留，不生成未经依据支持的 `valid:true`。不承诺尚未实现的通用 `asOf` 查询，也不让搜索接口直接裁决最终有效约束。

MCP 支持结构化返回和输出 schema，可以直接服务 Codex 等客户端。[工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)。扩展正文读取会扩大基线 MCP 的数据可见范围，应继续使用已确认项目身份和现有鉴权，只接受受控来源引用，不变成任意路径或任意 URL 读取工具。

### 两种使用模式

**启动恢复**：`get_work_context` → 检索 → 展开少量关键来源 → Agent 明确适用约束和不确定项。实验可先试验新增上下文约 3–4k tokens、8–12 条短候选；这只是预算变量，不是产品保证。

**执行中按需检索**：遇到跨模块修改、接口冲突、证据漂移或需求变化，再提出窄查询，优先补充新来源与变化内容，减少整包重复投递。

检索失败是否阻止某项高风险操作，由 AgentWorkflow 的规则决定；任务板如实报告检索状态。

### 性能、一致性与安全边界

1. 索引是可重建派生数据，不进入 claim、submit、verify 的提交事务，也不在这些操作中等待分词、Embedding 或重排。读取与索引工作要有并发、内存、扫描量和时间预算。
2. 不用当前有界 `eventsView` 充当无遗漏增量流。增量位置包含 commit 水位，必要时包含事件序号，并校验 hash；恢复或日志身份变化后重新核对索引。
3. 事件水位与文件观测分开。外置正文可以在 `projectRev` 不变时变化；索引与原文回读须携带各自内容身份和观测状态。
4. 保留历史归属边界：[现行契约](../CONTRACT.md)要求事件索引只认事件自带归属，跨实体关系查询期 join，不按当前 links 回填历史归属。见 [RFC-1](../decisions/rfc-1-history-read-model.md)。
5. 重复字段原文可去重并保留各版本引用，不同来源、状态和范围不能因文字相同而合并为同一权威事实。历史摘要按契约从数据机械生成，不用持久化生成摘要替代日志。
6. 索引不可用可退回有界扫描或来源目录，并说明覆盖不足；不能用空集合冒充没有约束。检索故障不阻断普通任务操作。
7. [现有正文边界](../WORKSPACE-DOCUMENTS-CONTRACT.md)由工作区和 Git 持有新文档正文。持久保存完整正文副本需要另行评估；实验可先使用临时索引。固定对象不可取时报告缺失，不用当前正文替代历史。
8. [架构](../ARCHITECTURE.md)限制 core 的依赖方向，[贡献指南](../CONTRIBUTING.md)要求新增运行时依赖先讨论。采用第三方检索库须明确随包依赖和模块归属；零用户配置不等于零工程依赖。

## 最小实验与评价方法建议

### 实验范围与样本

先做隔离检索实验，再做少量盲测任务。第一轮无需产品 UI、自动记忆写入、通用时点查询或完整约束模型。词法基线可复用 FTS5/BM25，MiniSearch 是纯 JS 集成候选；先比较中文处理、效果与资源开销，再选生产组件。

可从六类真实历史选择约 24 个问题：

| 历史主题 | 主要检查点 |
|---|---|
| 显式批准转自动固定 | 找到覆盖依据，避免恢复旧操作步骤 |
| 普通验收与审计门 | 区分普通任务、审计任务和人工兜底 |
| 历史读模型与查询规格 | 区分批准方案与已实现接口 |
| 外置正文与固定证据 | 区分元数据版本、工作区 hash 和 Git 内容身份 |
| 事件兼容、迁移与回退 | 恢复跨存储和发布层的限制 |
| 文档关联与历史归属 | 发现查询期 join 这一跨模块约束 |

每类包含直接关键词、间接表达、代码标识符，以及过时前提或证据不足问题。可借鉴 LongMemEval 的知识更新、跨会话推理、时间推理和拒绝无依据回答的分类；聊天问答成绩不能替代工程验证。[LongMemEval](https://github.com/xiaowu0162/longmemeval)。

每个样本需要人工核对的判定表，包含必需约束和原始来源、过时或越域诱饵、新旧规则关系、允许回答无法确认的部分，以及违反约束会产生的具体错误。待测模型生成的摘要不能当标准答案。

### 对照与隔离

| 组别 | 用途 |
|---|---|
| 现有方式 | 相同现行约定、现有 MCP 和文件读取能力，不额外提供历史检索服务 |
| 纯全文检索 | 测量词法索引收益 |
| 全文加关系与来源信息 | 测量关联扩展、版本和来源信息收益 |
| 混合检索加相同来源信息 | 测量语义通道额外收益 |
| 人工正确来源包 | 仅作失败诊断，区分检索失败与理解失败 |

各组使用相同模型、初始上下文、读取预算和停止条件。冻结测试集后再调参，按历史主题分开调参与验收样本。历史回放固定任务启动时的代码和语料，排除后续修复、验收答案和未来决议；无法恢复当时正文的样本标为不可完整回放。

检索指标通过后，可选择六个小型工程任务，比较现有方式、方案 A 和方案 B，各重复两次，共 36 次隔离尝试。该数量是实验设计候选，不是已安排执行的任务。

### 评价指标

| 指标 | 建议定义 |
|---|---|
| 关键约束召回率 | 正确恢复且有来源的必需约束数除以标准必需约束数，关键项单独统计 |
| 错误约束引入率 | 被当成适用约束的过时、越域或无依据条目除以采用的约束总数 |
| 有效性判断 | 对现行、被替代、范围不符、冲突、未知分别统计准确率 |
| 替代链恢复率 | 同时找到旧规则、改变依据和适用范围的比例 |
| 来源准确率 | 引用是否支持结论，内容身份是否吻合 |
| 不确定性处理 | 索引不完整或来源缺失时是否正确保留不确定 |
| 错误实现率 | 违反关键约束的任务数除以尝试任务数 |
| 上下文成本 | 检索、回读、重复投递和答案的实际 tokens，不直接用字符数代替 |
| 性能 | 查询和回读 p50/p95、冷建索引、增量延迟、RSS、索引体积及常规任务操作开销 |
| 维护成本 | 实现工时、依赖和部署增量、决策变更时需要的人工维护动作 |

故障样本应包括正文已变但 metaRev 未变、固定对象缺失、索引落后、重复事件文本、来源截断和撤销登记。真实数据副本和试测按[测试分级](../TESTING-POLICY.md)与[隔离环境](../TEST-ENV.md)执行。

采纳依据优先看错误实现是否减少。召回上升但错误约束增多、Token 显著增加或常规操作变慢，不能据此升级架构。若人工正确来源包仍不能降低错误，应改善 Agent 核对方式或流程，而非继续增加检索组件。阈值须在实验前约定，小样本结果只作方向判断。

## 留待方案阶段讨论的问题

| 问题 | 选项与取舍 |
|---|---|
| 语料覆盖 | 仅看板和登记文档边界清楚；加入指定仓库文档提高覆盖。实验可用明确清单，生产默认范围待定 |
| 正式决定的依据 | 原文由 Agent 判断维护成本低；明确批准依据更便于核对。`done`、`adopted`、`kind=decision` 不自动等于约束有效 |
| 范围与替代声明 | 保持现状或在既有文档和验收动作中增加少量元数据，由有效性失败样本决定收益 |
| 随包依赖 | 纯 JS 库易集成，内置 SQLite 受运行时限制，独立服务运维较重；须符合开箱即用方针 |
| 模型与正文外发 | 本地词法无需外发；语义检索涉及本地模型或外部服务，是否允许及降级方式待定 |
| 正文缓存 | 临时索引接近现有正文所有权，持久索引启动更快；需定义失效、保留和清除边界 |
| 产品承诺 | 可追溯材料与覆盖报告具有现有基础；保证恢复全部有效约束需要额外治理语义和验证 |

这些问题用于下一次方案讨论，不改变[已确认方向和唯一目标](../decisions/structured-continuous-knowledge-base.md)，也不构成技术选型或实施授权。
