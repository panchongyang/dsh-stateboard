# 实施方案：项目摘要按字面文本进入宿主 Prompt（F01）

状态：F01 实施方案记录。公开候选源码已实现该方案并包含回归用例。支持版本验证与部署状态按各候选记录。

## 1. 决策目标

项目名、任务标题、checkpoint 等板上文本是数据，不是宿主模板。它们进入 `project:brief` 后必须保持摘要生成器给出的字面内容，不能触发变量查找、替换或模板语法错误。

本项的治理原则遵循 [产品方针三](<../PRODUCT-PRINCIPLES.md#方针三变更安全性与长期可维护性是一等工程质量属性>)，不与 open 职责治理互相阻塞。

## 2. 变更前的机制

- `project:brief` 先前注册为普通动态 section，宿主会对摘要运行模板解释。
- [buildDigest](<../../lib/core/digest.js#L12-L32>) 清洗控制字符、折叠空白并截断字段，但保留双花括号。
- 宿主包 `@deepseek-ai/dsh-system-prompt` 的 `renderPrompt` 默认解释模板。未知或畸形变量会抛错，已注册变量会被替换。section callback 的异常处理无法捕获返回后的渲染异常。
- 支持字面模式的宿主通过 `assemble` 保留 section 的 `interpolate` 属性。可用性在[宿主回归](<../../test/host/host-audit.test.mjs>)中验证。

## 3. 方案：在插件与宿主的接口处声明文本语义

在 `project:brief` section 定义中声明字面模式。

```js
scope.systemPrompt.section({
  name: 'project:brief',
  order: 9000,
  interpolate: false,
  text: () => { /* 保留现有动态摘要与异常处理 */ },
});
```

这是接口语义声明，不是针对若干字符打补丁。摘要内包含固定规则说明也不意味着它需要模板插值；当前实现未显式依赖模板变量。

必须保持：

1. 继续动态生成摘要，不在安装时固化旧字符串。
2. 继续保留控制字符清洗、字段长度上限与“板上内容是数据”的说明。
3. 未知、已知、畸形模板引用均按字面展示，不能把未知变量注册为空或悄悄删除文本。
4. 只改变项目板 section，不修改宿主全局模板策略，也不影响其他插件有意使用的模板。
5. 不因某标题而重写或迁移项目数据，不改变日志/schema。

本方案消除的是宿主模板解释问题，不宣称解决所有模型提示注入或不可信文本风险。

## 4. 不推荐的替代方案

| 方向 | 不推荐原因 |
|---|---|
| sanitizeField 删除/改写所有双花括号 | 把宿主语法知识扩散到核心格式化函数；破坏合法示例文本，其他文本通道还可能遗漏 |
| 全局放宽未知变量错误，或让外层 catch 丢弃整个摘要 | 影响其他插件的正确模板契约，或以丢信息掩盖问题 |
| 为每段动态数据注册模板变量 | 增加字段映射与状态约定；当前整个 section 都是已生成文本，没有必要再模板化 |

## 5. 实现与测试入口

- 运行时：现有 [prompt adapter](<../../lib/host/prompt.js>) 的 section 声明。
- 测试：现有 [Prompt 隔离测试](<../../test/ops/prompt-health-isolation.test.mjs>) 断言真实注册对象的 interpolate 属性；宿主回归验证真实 assemble/render 的集成行为。
- 测试接线：[host 审计测试](<../../test/host/host-audit.test.mjs>) 由默认 host 测试命令执行。
- 如现有支持版本不具备该能力，按真实版本测试结果调整兼容承诺；不通过字符串转义兼容层悄悄兜底。

宿主集成测试通过项目现有宿主发现方式定位已安装包，用其公开解析入口载入 SystemPrompt/renderPrompt；禁止将本机服务绝对路径硬编码进可提交测试，也不新增产品运行依赖。

## 6. 验证矩阵

| 场景 | 必须断言 |
|---|---|
| 捕获 installPrompt 的真实注册参数 | interpolate 严格为 false，而不只检查 callback 返回字符串 |
| 项目名含未知模板变量 | assemble → render 无异常，摘要文本中的引用保持字面 |
| 标题含与宿主已注册变量同名的引用 | 不被替换，宿主变量哨兵值不泄入项目摘要 |
| 畸形引用、单侧花括号、代码示例、Unicode | 不被当作模板解释；按既有清洗/截断后的摘要保持内容 |
| 当前会进入摘要的任务标题、checkpoint 等字段 | 分别验证实际进入摘要后无模板解释，不用未被选择/已被截断的字段制造假通过 |
| 状态更新后再次 assemble | 摘要动态更新；无项目/关闭 handle 仍输出空文本 |
| 非项目板的正常模板 section | 仍正常插值，未知变量仍遵循宿主原契约 |
| Prompt 热路径 | 保持不触发加载、同步 Git/正文 I/O 或深审计 |

集成层必须使用真实宿主 section 注册与 assemble/render，让测试能捕获属性在中间丢失的问题。无需启动真实 DSH、模型调用、HTTP 服务或浏览器。
