# 历史知识读取与检索：最小实施方案

> 状态：已实现 DSH/MCP 同名两层读取与独立派生索引；索引的验证与独立审查范围见[验证记录](../decisions/history-knowledge-validation-2026-11-14.md)。宿主是否生效取决于部署。
> 调查基线：`dca3d73`；实施基线：`3737a09`。
> 上位方向：[结构化连续知识库与下阶段唯一目标](../decisions/structured-continuous-knowledge-base.md)。背景材料：[技术调研](../research/history-constraint-recovery.md)。

## 1. 已确认的本阶段目标

打通任务板已有数据，建立独立的历史知识读取与检索能力，使外部 Agent 能通过统一读取服务搜索历史碎片，再沿引用读取具体历史原文及有界上下文。

- 来源是任务、计划、事件、登记文档、证据、审查记录与已有关系。外置内容只能通过登记文档或任务证据进入，不扫描整个工作区。
- 检索读模型是派生数据，不改变权威记录、领域写模型、提交与验收语义。相关性、来源事实与适用性分别表达。
- 本方向是当前最高优先方向，可以取代传统历史读计划。传统历史读暂停开发，不作为前置条件或并行工作；未被本阶段覆盖的旧能力仍暂停。
- 采用两层读取：先找碎片，由 Agent 选择并深入原文和局部上下文。任务板不自动生成记忆或裁决约束有效性。
- 不引入 Embedding、向量数据库、GraphRAG、独立约束实体、产品 UI 改造或任务管理重构。

### 积累与重建的承诺

任务板和检索服务可能间歇使用。没有被记录、观察或保留下来的内容，不承诺追溯补齐；不假设持续运行或捕获了全部工作历史。

**重建针对已经实际积累并保留的材料。** 本阶段复用任务板已有留存材料，不另存外置正文快照。日志与内嵌档案、仍可验证读取的固定 Git 内容是重建来源；只有引用和 hash、没有可用原文的外置内容，不能视为已留存正文。源对象丢失时报告缺失，不能靠索引恢复或用当前正文替代。

索引中的历史命中与当前原文可用性分开报告。对仍保留的来源，重建应恢复相同引用与内容；对已不可取的来源，重建保留可取得的记录和缺失状态，不声称完整恢复。

手动重置基线保留为后续议题。本阶段只提供明确覆盖信息和可失效的派生索引，不预建基线重置命令、历史截断或新的事实库生命周期。

| [证据](../../lib/core/evidence.js)与[审查](../../lib/core/audit.js) | evidence ID、验收关联、替代信息、固定引用、审查报告与范围指纹 | 文件证据按可证明路径和内容身份读取；只有 ref/hash 不等于保存了正文，报告仍为提交者自述 |

当前 read 连接的四个概览工具与项目授权通道的数据范围不同。后者的 get_project_view 已能读取正文，需项目范围授权与工作会话；不能把旧调研基线的“只有四个工具”当成当前全部 MCP 能力。

旧历史方案的通用 asOf、HTTP /history、固定分段阈值不作为本阶段验收条件。仍遵守现行的数据边界：历史事件归属只认事件自身；跨实体关系在查询期解析，不按当前关系改写旧归属。见[现行契约](../CONTRACT.md)与[RFC-1](../decisions/rfc-1-history-read-model.md)。

## 3. 来源清单与历史原文含义

| 来源 | 索引内容与原文定位 | 历史和覆盖边界 |
|---|---|---|
| 任务 | 标题、描述、验收要求、记录中的说明；定位到 commit、事件位置、字段及任务版本 | 搜索按任务展示最新匹配版本；用同一查询和 `historyRef` 展开历史匹配，每版本保留原引用 |
| 计划 | 计划头与各内容版本中的名称、描述、阶段和已保存正文 | plan ID 是身份，version 是内容版本；不把管理 rev 混成内容版本 |
| 事件与交接 | 已支持事件的可公开字段、checkpoint/handoff、执行意图与结果记录 | additive 事件也可有独立知识；只读 current state 会漏掉这部分 |
| 登记文档 | 登记元数据、既有内嵌正文、可读取的外置正文、已记录固定版本 | 外置 metaRev 不等于正文版本；未被保留的文件旧字节不可恢复 |
| 证据 | kind、ref、summary、hash、验收关联、提交者与替代记录 | doc 引用沿现有读取域展开；file 只有在可证明项目路径与内容身份时读取；不按相似路径猜测 |
| 审查 | 历史任务记录中的 lastAudit、报告、清单、结论、范围与证据指纹 | 记录“谁作出了什么报告”，不转成系统认定的正确性事实 |
| 关系 | 任务依赖、planRef、文档 links、证据到验收项、明确的证据替代 | 按读取水位在查询期展开；不生成语义推断关系 |

具体材料使用与现有授权读取一致的公开投影，保留原始文本并剔除内部租约、执行凭据、本机绑定根与绝对文件引用；字段省略与正文截断不能冒充完整内部记录。

外置正文候选只来自登记与证据引用。URL、command、test 类型首先作为记录读取，不抓取任意远程链接，不重新执行命令或测试。普通文件证据缺乏可证明的定位、已越界、hash 改变或格式不支持时，只返回证据记录及相应状态。沿用既有文本格式与读取限制，首版不额外增加 PDF、图片或源代码解析器。

撤销登记、绑定失效或权限撤销后，停止相应当前正文的自动读取与命中交付；历史登记记录仍可追溯。固定历史内容是否可读继续服从现有授权与内容身份校验，不因索引曾命中而获得额外权限。

## 4. 两层读取契约

统一 core 知识读取服务，DSH 原生工具与 MCP 提供同名的两个薄适配入口，共享业务 schema、描述、原文与来源/覆盖返回。DSH 按受信会话 cwd 定位项目，MCP 使用项目工作会话授权；业务能力同步交付，不能漏接一端。具体字段以 [CONTRACT §8.1](../CONTRACT.md#81-历史知识读取与检索) 和 [shared](../../lib/shared/knowledge.js) 为准：

| 入口 | 输入 | 返回 |
|---|---|---|
| search_project_knowledge | 关键词、可选来源类型、结果与关联预算、分页游标、调用者联想线索；MCP 另传项目与工作会话 | 碎片、来源引用、命中信息、来源版本、覆盖情况 |
| read_project_knowledge | 一个或少量来源引用、原文或上下文模式、字节预算、续读游标；MCP 另传项目与工作会话 | 公开原记录或正文块、已有关系及可继续展开的引用、内容身份、缺失与截断状态 |

第一层优先摘录描述、说明、验收条目等业务原文，保留来源引用和版本状态；定位哈希和 actor 在第二层原文提供。第二层展开所属记录、正文块和必要前后文，单次最多自动附带一跳已有关系。单次返回条数与总字节数有上限，后续跳转由 Agent 主动选择。不同版本不混为一段“完整历史”。

第一层可附带由已有关系发现的碎片，与直接命中分开并说明理由。模型动态联想由调用 Agent 提出新查询；调用可携带父引用和理由，但只标为待核对线索，不落项目正式关系。先允许模型自由跳跃，不预设累计轮数、总跳数或搜索方向，不要求新查询沿已有关系。任务板只控制单次资源/响应成本和自动附带的一跳关系，不承担模型思考流程门禁。

### 引用身份

引用绑定项目、来源类型、实体 ID、commit seq/hash、事件位置和字段或章节定位；正文引用再包含对应 rev、hash 或固定 Git 身份。数据库行号与索引代号不作为持久来源身份。索引重建后，相同仍可用来源的引用继续可解析。

任务与计划的“原文”是记录中的原始字段或结构化内容，明确标识读取范围；不声称返回包含内部凭据的完整 commit。commit hash、正文 hash、公开记录投影 hash 分别标明计算对象，不互相替代；搜索片段沿来源 hash 回读，不表示片段本身的 hash。

引用不是授权。每次读回都校验项目范围、来源存在性与身份，不接受任意文件路径、任意 URL 或调用者自行拼接的跨项目定位。来源变化时返回 changed/missing 等事实；读取最新内容须使用其独立引用。

### 版本与关联

历史读取支持精确保存版本，不承诺通用时间旅行。事件、任务历史字段、计划版本、内嵌 doc rev 和已记录固定引用各有明确定位。

上下文以命中记录的版本为锚点。明确版本的关系直接读取对应版本；只有稳定 ID 的关系，返回关系声明及候选目标引用，并标明目标读取水位。第一版不把当前关联目标悄悄包装成旧时点状态，也不为此新增全项目 asOf 投影。

新旧替代只有在原始记录明确表达时才展示为已记录关系。证据 supersededBy 不自动表示设计决定被废止；无法确认的冲突交给 Agent。

### 覆盖情况

每次响应区分三件事：

1. 已知材料：本次纳入哪些来源、已验证和已索引到哪些日志范围；未纳入或未读取的数量及原因。
2. 观测状态：外置材料的独立观测时间、内容身份、可读性和已知变化；日志水位不证明外置正文最新。
3. 返回范围：候选、原文与关联是否截断，是否还有游标或未展开引用。

complete 只能相对于明确列出的材料范围和读取水位使用，不表示记录了全部项目历史，也不表示恢复了全部约束。零命中不等于不存在约束。

## 5. 索引与生命周期

### 检索实现

使用 Node 内置 SQLite 的 FTS5/BM25，索引运行在独立 worker。core 继续仅依赖 node:*、shared 与 core；不新增外部服务或用户配置，不自研 BM25。

使用 contentless-delete 全文表，单独保存来源定位、版本、hash、范围和进度；片段与原文从来源回读。索引不保存可回读的正文列，重建由重新枚举来源完成，不依赖 FTS 的 rebuild 命令。词项仍可能暴露内容，索引服从同一项目的本地权限与返回授权。

插件声明 Node >=22，运行时动态检测 SQLite/FTS5 的实际能力，不要求用户加开关、安装扩展或升级才能使用主流程。SQLite/FTS5 不可用时，复用同一来源适配与引用契约，降级为有界关键词扫描，明确标记引擎、覆盖与预算耗尽；扫描排序为关键词匹配计分，不标成 BM25。

查询接受普通关键词，不开放原始 SQL/FTS 表达式。词项做 NFKC 与小写归一化，中文保留单字/双字组合，英文标识符保留完整形式与组成部分；连续中英分别识别。FTS 使用编码后的原子词项，优先按 AND 匹配。零命中时可按词组覆盖放宽，显式报告匹配和缺失的词组。分词版本进入索引格式标识；具体实现见 [terms](../../lib/core/knowledge/terms.js)。

### 生命周期

1. 首次授权查询按需建立来源清单和索引；没有查询不持续运行。未完成追赶时，coverage 返回已验证/已索引水位、lag 和正文未观测数量。
2. 索引位于独立的本地派生缓存目录，不写入权威 store 的 meta、commits、snapshot 或 blobs。缓存格式带版本，损坏或不兼容时失效并重建。
3. 后续调用按已验证水位追赶，不另启常驻后台循环。进度只在一个完整 commit 的材料处理完后前移，来源记录保留事件位置以防漏项和重复。
4. 仅对已知来源重新观测。外置文件变化不依赖 projectRev；不能仅凭登记版本未变就跳过所有正文变化检查。回读关键正文时重新核对 hash。
5. 重建在独立事务中重置并发布已校验的来源批次；增量也在同一派生事务中发布数据与水位。分批重建公开落后范围，不假装完整。每次内容变化更新索引代号；分页游标钉住代和水位，续页不推进派生索引，代变化后明确要求重查。来源引用不依赖代，仍可单独读取。
6. 索引落后但与源历史仍同源时，可返回已有范围并标记落后。日志缩短、替换、回退或身份无法证明时停止把旧索引作为当前结果，重新核对来源。
7. 每次请求结束释放 worker 和内存；再次调用继续核对缓存及已留存来源。关闭、超时或 worker 失败只影响检索请求，不影响任务操作。

取消登记与来源不可用都需要更新材料状态。外置当前正文的旧词项可以失效，但不删除任务板中的原始记录，也不把未保留的外置旧正文制造成历史档案。

## 6. 一致性、性能与架构边界

读取链路为：host DSH 受信工作区定位或 MCP 授权与参数翻译 → core 知识读取服务 → 有界来源读取与索引 worker；shared 定义业务 schema、描述、来源类型、工具名称和资源限额，core 统一校验请求与引用。两侧均不打开 writer 或 touch 租约，DSH 原生工具不依赖 MCP 开关，原文返回不经过管理工具的短文本摘要。既有文档/Git 守卫在 core 复用，host 不复制领域判断；模块进入现有架构清单，不增加多引擎插件框架。

### 权威来源的一致性

- 优先复用 writer 已发布的提交水位，按有界批次读取已提交记录，不发送整个 state/commits 给每个搜索请求，不增加写事务回调。
- 冷读取沿用完整 commit 校验、事件兼容与文档/固定证据守卫，不用只解析 JSON 的宽松旁路。不能用 timeline 的尾部或当前任务视图推导历史完备性。
- 每次请求都执行完整源日志校验；只有派生索引按完整 commit 增量追赶。源文件单个上限 64 MiB，读取窗口变化最多重试一次；不把 mtime 或最后一条 seq 当成日志健康证明。
- 索引水位与关联读取水位分别记录。跨实体展开在查询期读取，保留读取版本，不按当前 links 回填历史归属。
- 外置文件不与日志构成原子快照；分别返回日志范围和文件观测身份，不能承诺二者处于同一时刻。

### 运行预算

索引不进入 claim、submit、verify、事件追加、快照写入或启动恢复的成功条件，不持有项目 writer 锁。索引损坏、缓存写失败、SQLite 不可用或超时均不得使原任务操作失败。

单次预算：同一宿主最多一个知识读取 worker，独立于现有只读 worker 名额；请求 30 秒截止。搜索默认 20 条、最多 50 条，关联默认最多 10 条、上限 20 条并占用总条数；至少一半位置留给直接命中。原文单块最多 24 KiB，单次最多 8 个原文引用，总响应最多 256 KiB；超出正文分页或明确报限。索引批次最多 4000 条记录、32 份/32 MiB 正文；32 MiB 仅是索引正文观测预算，不是全请求 I/O 上限。完整上限见 CONTRACT；不限制 Agent 的累计联想轮数。

CPU、磁盘与内存开销不可能绝对为零。“不影响可靠性”指没有写路径耦合或错误传播，并通过资源预算与配对测试控制竞争。SQLite 原生内存不受 V8 old-generation 限制完整约束，须同时限制数据库缓存、工作批次、原文读取与结果缓冲，并测量进程 RSS。

沿用当前项目授权读取通道，纯读取不要求领取任务、写入 intent 或执行验收。现有概览 read token 不自动升级为历史正文权限。独立的细粒度只读凭据属于后续权限产品议题，不通过本功能偷偷放宽。

## 7. 验证与交付

实现涉及历史来源校验、持久派生缓存、证据读取和 MCP 数据范围，按 R3 管控：独立分支/worktree、合成 fixture、隔离运行环境、最终候选独立审查。本阶段不运行真实数据试测或部署。见[测试分级](../TESTING-POLICY.md)与[隔离环境](../TEST-ENV.md)。

| 测试组 | 必须验证的结果 |
|---|---|
| 历史来源 | 快照前后、单 commit 多事件、additive 事件、旧计划、被替换证据、历史审查均可定位；不是只命中当前 state |
| 来源逐项对照 | 用人工可核对的合成原始材料清单比对来源 ID、版本、字段与 hash；不能用同一抽取实现生成期望答案 |
| 重建 | 清空或隔离派生缓存后，对仍留存来源恢复等价引用和内容；缺失正文保持缺失，不从索引伪造 |
| 增量 | 分批、重复批次、批次中断、同 commit 多事件、进度提交失败均无漏项或重复事实 |
| 间歇使用 | 停用后有新事件、正文变化或对象丢失；恢复调用准确报告累计范围与缺口，不宣称捕获停用期间所有文件版本 |
| 一致性 | 并发追加、读取中变化、日志回退/替换、同 seq 不同 hash、索引落后、分页代失效有明确结果 |
| 正文 | metaRev 不变而正文改变、文件改名/删除、固定 Git 对象丢失、内嵌迁移、hash 不符、不可解码与超大文件 |
| 授权 | 跨项目、伪造引用、过期会话、路径穿越、符号链接、外层仓库、撤销登记与绑定失效被现有边界拒绝 |
| 两层读取 | 搜索片段 → 原始正文块/记录 → 有界关系；版本不混用，来源展开前后变化可见；预算耗尽有续读或截断说明 |
| 关键词 | 中文短词、中文长句、英文接口名、错误码、否定句、重复版本；排名不改变来源状态 |
| 故障隔离 | 缓存不可写、索引损坏、worker 超时/失败、SQLite 缺失期间，任务正常提交与验收仍正确且事件完整 |
| 性能 | 配对测量索引关闭/开启时的任务操作成功率与 p50/p95、事件循环延迟、构建与追赶耗时、查询延迟、RSS/磁盘、实际上下文用量 |

来源回读、关键词索引与 MCP 两层读取属于同一阶段交付，以外部 Agent 的搜索到原文链路可用为验收对象，不以“索引已生成”为终点。

定向测试已进入现有 suite，check:strict、check:architecture 与 MCP/host 回归结果见验证记录；跳过和未覆盖项目分别列出。样本包含跨快照历史、来源丢失和普通任务提交/验收并发。当前只冻结资源上限和严重回归检查，不把合成观测或旧历史方案的阈值当成容量与性能承诺。

回退只撤回检索适配与忽略派生缓存，权威 store 与用户文档保持原样；不得通过重写日志或迁移任务数据修复索引。缓存不能成为恢复源文件的唯一依据。

## 8. 已确认范围与后续问题

已确认：当前优先级、传统历史读暂停、两层读取、现有来源范围、无工作区全盘扫描、不归档外置正文、有限重建承诺、手动重置基线暂不实现。

已实现的最小组合：FTS5 contentless 派生索引及有界扫描降级；稳定来源引用与按需展开；复用现有项目授权通道；按需追赶、明确覆盖与来源变化。验证结果、修正项和未覆盖范围见[验证记录](../decisions/history-knowledge-validation-2026-11-14.md)。

后续仍需通过缺少历史上下文的 Agent 任务实验，判断检索是否减少错误实现，并评估召回率、错误约束引入、Token 与延迟；本阶段合成读取验证不替代这项效果评估。更大日志容量、细粒度只读凭据和手动基线重置分别按实际需求讨论，不预建实体或工作流门禁。
