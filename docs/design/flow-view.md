# 推进视图（Flow）

> 状态：推进视图可从项目板切换打开。首次打开仍显示看板。默认视图切换取决于人工验收。

## 1. 定位

推进视图回答两个问题：**此刻在跑什么、什么在等我**。列表支持按计划分组扫读，五列看板继续提供按状态浏览。可使用 `?view=flow` 打开推进视图，并用 `project` 查询参数指定项目。

## 2. 为什么不是五列

五列看板的假设是「多人并行、列即状态、卡片相互独立」。单人 + AI 的实际数据不满足这四条：

- **并行量小且不稳定**：进行中通常 0–1 张（`maxInProgress` 当前为 5），评审 0–3 张，两列大部分时间空着；未来并发上限会调整，但「不需要常驻占位」不随之改变。
- **决定下一步的是依赖，不是列**：未完成任务之间的边大多是「未完成 → 未完成」，原型快照里最长链 11 层。
- **待办不是工作池**：快照里 45 个待办全部是「前置未完成」，不该与可执行任务占同等位置。
- **计划边界在五列里看不见**：活动计划、计划外、归属失效混在同一列里。

以上数字来自 2026-11-06 的原型数据快照，用于说明形态，不作为长期指标。

## 3. 页面结构

```text
┌ 现在 ─────────────────────────────────────────────────────────────┐
│ 正在推进（n / maxInProgress）│ 需要处理（待验收 / 待审计 / 异常）       │
│ 各会话的执行意图与解锁数     │ 优先展示异常与停留较久的待处理任务       │
│ 并行余量 · 就绪候选                               完成度 · 健康     │
└──────────────────────────────────────────────────────────────────┘
┌ 计划泳道（每条活动计划一条，可折叠）─────────────────┐ ┌ 右栏 ────────┐
│ ●计划名 [聚焦] ▬▬▬▭▭ 步骤进度 4/12      进行1 就绪3 等待4 │ │ 就绪队列     │
│ ✓4 ┄┬ [进行中卡] ━━━━┓      ░ 等待前置完成 ░            │ │ #1…#8 派发顺序│
│     ├ [#3 就绪卡] ━━━╋━━○ 站点 ━━━○ 站点              │ │ 最近完成     │
│     └ [#6 就绪卡] ━━━┛    ○ 站点            +5 站 →    │ │ 人工/AI自述/自动│
├ 计划外：卡片网格 + 「等待前置」票据                      │ └──────────────┘
└ 归属失效（默认折叠）：引用已归档/被修订掉的计划版本        │
```

- **现在带**：分别展示正在推进和需要处理的任务，计数可打开各自的任务清单。项目有并行余量时，底部显示全局就绪队列靠前的候选。
- **计划泳道 = 线路图**：左端绿色胶囊是该计划已完成数；**前沿**（进行中/评审/阻塞/就绪）是完整卡片；**等待前置**的任务退到后方灰底区，只是线上的站点（圆点 + 两行标题）。线 = 依赖；粗实线从前沿出发，细线连接后方站点。卡片上「→ 解锁 n」表示完成它能推进几项。
- **悬停/聚焦**：高亮该任务上下游整条链，其余淡出；URL `#focus=<taskId>` 可固定。
- **右栏**：就绪队列按 core `nextPriority` 的派发顺序编号；最近完成标明验收方式，AI 审计明确写「AI 审计（自述）」。
- **无依赖的计划**退化为按计划步骤分列；计划外与归属失效用卡片网格。

## 4. 已定口径

### 4.1 现在带

- **正在推进**最多预览三张，优先覆盖不同执行会话。会话有标题时显示标题，缺少标题时显示短 ID。计数列出全部进行中任务，包括仍占用进行中状态的超期任务。
- **需要处理**分为待验收、待审计、异常三个入口。异常包括阻塞、待对账和执行超期。预览保留最多两张，按紧急程度和停留时间排序。
- **计数打开对应清单**。清单以浮层覆盖泳道。窄容器按顺序堆叠两个分组。
- **`maxInProgress`**用于计算并行余量。就绪候选按全局派发顺序展示，具体领取仍按领取规则判定。完成度和健康入口放在底部。
- **卡片不挂 worktree / 分支 / 候选 commit**，也不做隔离就绪度之类的派生信号。

### 4.2 泳道

前沿区放完整卡，后方站点只留圆点与两行标题；线表示依赖。泳道保留前沿窗口内的任务与命中聚焦或搜索的节点。

### 4.3 搜索与聚焦

搜索命中高亮、未命中淡化，**不移除节点**（过滤会打断依赖线）；含命中的折叠泳道自动展开；点击卡片打开抽屉，同时在该泳道 focus。

### 4.4 右栏

就绪队列按 `nextPriority` 编号；最近完成标明人工验收 / AI 自述 / 自动，与「不伪造」方针一致。

## 5. 与现状语义的差异

1. **# 编号只给就绪任务**：与 core 派发顺序一致；等待前置的任务不再有号。
2. **`backlog` 显示为「待前置」**；若出现「依赖已满足但无验收项」的 backlog，站点显示「未就绪」。
3. **删除**五列、「需要你 / 完成度」两块统计砖、状态筛选 chips；推进页由结构本身分层。
4. **归属失效泳道**：`planRef` 指向已归档计划或旧版本、不在任何活动计划当前版本里的任务；只提示，不自动处理。

## 6. 已知布局局限

原型刻意没做以下优化，人工验收后再决定是否处理：

| # | 问题 | 现象 | 可选方向 |
|---|---|---|---|
| L1 | 无交叉最少化 | 跨层长边水平穿过别的折线 | 层内排序做 barycenter 多轮扫描 |
| L2 | 汇入同站点的多条线共用竖线 | 多源→一站时像总线 | 入口错位（端口分配） |
| L3 | 长链 | 11 层默认截到 5 层 + 「+N 站」 | 折叠中段为「…k 站」或纵向布局 |
| L4 | 跨计划依赖不画线 | 只在站点上显示「等 · 某计划」芯片 | 泳道间连线 / 芯片跳转 |
| L5 | 站点标题截断 | 136px × 2 行，靠 tooltip 与抽屉 | 悬停展开标签或加宽层间距 |
| L6 | 前沿全部堆在第 0 列 | 计划内就绪很多时泳道很高 | 前沿超过 N 张折叠为「还有 k 张就绪」 |
| L7 | 环 | 已防死循环但不显示 | 交给健康页报告 |
| L8 | 窄屏 <900 未设计 | 线路图只能横滑 | 窄屏改纵向线路或退回列表 |
| L9 | 计划配色 | 按 id 取 10 色，部分偏近 | 固定 8 色 token（含暗色） |
| L10 | 规模 | 原型需覆盖常规与大任务量 | 折叠泳道不渲染画布 |

## 7. 产品化拆分

| 阶段 | 任务 | 产出 |
|---|---|---|
| 内核 | 读模型增补 | 任务卡 `deps`、计划步骤 `taskIds`、进行中任务的执行意图摘要；只读字段，不改状态机与命令，独立审查 |
| 内核 | 布局纯函数 | 分层、层内行号、前沿窗口截断、链高亮集合；不依赖 DOM，可单测 |
| 视图 | `src/client/components/flow-view.tsx` | 现在带、计划泳道、右栏、搜索与 focus、降级形态 |
| 接入 | `src/client/pages/board-page.tsx` 视图键 `flow` | 可切换、可 URL 直达；默认仍为看板 |
| 收口 | 人工验收后 | 切换默认视图，更新本文与 CHANGELOG |

## 8. 测试与验收

- **单测**：分层、行号、窗口截断、链集合、计划分组。
- **数据夹具**：`cap=2 + 10 张进行中`（测超配信号）、`cap=10 + 10 张进行中`（测布局不随上限变）、2000 任务合成（测规模）。
- **人工验收**：交互与视觉按[贡献指南](<../CONTRIBUTING.md>)由人工验收。

## 9. 原型验证范围

原型仅用于验证离线布局与交互。公开复现使用上文的合成夹具。

## 10. 边界

- 不改状态机、命令形状与 HTTP 路由；读模型新增只读字段。
- 不引入 worktree / 分支 / 候选 commit 字段；worktree 设计草案的口径不适用于本视图，相关前置问题后续以软依赖方式处理。
- 不新增浏览器探针；交互与视觉由人工验收。
