# 最小身份闭环与兼容验收方案

## 状态与边界

这是待实现的方案约束与验收输入，不宣称当前已支持。v0.1的项目文档正文由工作区/Git持有；看板任务、计划、租约、事件、执行密钥、文档登记/人工状态和本机绑定继续用户级集中存储。完整项目内状态存储、远端同步及多人协作独立规划。本方案不授权真实数据搬迁或历史日志改写。

身份任务等待首发决策与文档外置契约，再为文档登记提供稳定身份与本机绑定。文档外置实施另见[工作区方案](<../../docs/WORKSPACE-DOCUMENTS-PLAN.md>)，不重复建设身份发现。

## 核心模型

- projectId创建后永久稳定。新项目随机ID，现有项目保留原ID，包括由路径哈希产生的ID，不重算、不改历史。
- 本机绑定记录项目在本机的主工作区和获准别名/工作区，不是逻辑身份或跨设备共享绝对路径。
- 看板状态继续现有用户级根管理；稳定ID、Git文档正文或项目标记不表示看板数据已跨机存在。
- 会话目录用于项目发现及会话代码上下文，不能覆盖共享handle主工作区。文档读取所选绑定必须显式且可见，不由会话cwd隐式切换。
- 既有file证据继续主工作区验收策略；worktree共享看板不等于任意分支产物已合入。新增文档固定内容证据通过明确仓库绑定/commit/路径/blob定位，不把分支内容身份解释成合入或部署证明。

项目标记或显式绑定注册表的精确格式在实施前确认。若采用项目标记，只含schemaVersion与projectId，无绝对路径、凭据、执行命令或宿主配置。Git只辅助发现同一本机仓库，不以remote、仓库名或提交hash生成逻辑身份。非Git项目有显式绑定路径；非Git文档可登记阅读，正式可重放Git证据的限制由文档契约定义。

## 发现和冲突规则

1. 显式项目/绑定优先并校验，不通过任意projectId越权读写；保持角色、路径和人审边界。
2. 子目录向上查最近合法项目标记/绑定，嵌套项目与仓库边界有可测试停止规则。
3. worktree可经Git common-dir辅助识别本机同仓库绑定，不假设.git一定为目录，不按父目录猜项目。无显式标记的自动关联必须无歧义；多个worktree共享看板或文档读取绑定仍须明确获准，不跨root补读同名文件。
4. 无显式绑定的既有项目可按路径索引发现；显式标记与路径索引冲突时拒绝，不静默选择或合并。
5. 移动/改名识别原ID，经用户确认更新本机绑定；旧路径仍有效或目标已绑其他项目先报告冲突。
6. 同机重复clone/复制，明确选择连接已有项目或建独立项目；新项目分配新ID，不改原历史。
7. 跨机显式导入用户选择的数据副本并重绑，保留ID/日志/关系；工作区正文随Git，登记与管理状态来自看板数据导入。只有标记/正文而无看板数据时提示“数据未导入”，不伪造历史、不自动同步或建空项目替代。
8. 畸形标记、路径穿越、链接越界、未知schema、竞争绑定及迁移中断可诊断拒绝，不重复建项目、覆盖绑定或接管邻项目。

## 迁移与恢复

先列旧项目和映射，提供dry-run、人工确认及必要备份。区分派生缓存/本机绑定与权威日志，不直接编辑历史事件作为迁移。复用原稳定ID、relocate、自愈和锁；若改事件/元数据schema，事前声明兼容分类、旧版拒读、代码+数据回退和恢复测试。

禁止真实store作为试验对象，默认合成旧版fixture。真实数据导入、文档导出或切换需对应授权、一致性备份与用户手动运维。项目标记和Git文档不能替代看板状态备份。

## 验收矩阵

| 场景 | 必须验证的结果 |
|---|---|
| 旧项目打开 | 原ID/任务/计划/关系/历史保留，正文来源和兼容档案按文档契约标识，不强制先迁移才能读 |
| 目录改名/移动 | 确认重绑后同项目，重启正确、不重复创建 |
| 子目录/嵌套项目 | 最近所属项目发现正确，不串父级/邻接项目 |
| 主仓库/worktree | 同看板/ID；主工作区和file证据根不被会话切换，文档上下文明示 |
| 重复clone/fork | 连接/新建显式选择；独立项目新ID，原历史不变 |
| 无Git/无网络 | 显式绑定和文档登记阅读可用，不依赖remote可达；Git固定证据限制明示 |
| 换机合成导入 | 路径不同，ID/历史/关系保持，内容解析与证据只用目标机获准来源 |
| 仅身份标记/文档正文 | 明示看板数据缺失，不声称状态同步、不建空历史顶替 |
| 冲突/恶意标记 | 可定位拒绝，无日志/文件覆盖/接管副作用 |
| 并发/中断 | 单写者保持，绑定原子性、恢复和幂等成立 |

## 实施与留证

按R3：专用分支/worktree、独立home/workspace/board/认证，先风险/回退再合成测试；冻结候选后完整门禁、独立审查与受影响UI人验。身份发现至少覆盖会话attach、工具resolveHandle和项目创建/打开，不能只修单入口。
